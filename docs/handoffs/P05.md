## Decisions taken under ambiguity
* D1 App/URL installation without editing `backend/erp`: `backend/ledger/conftest.py` installs the app for pytest
  (CCR P05-1); `ledger.testing.settings_dev` for local runs. Service autoregistration is disabled in that bootstrap so
  the kernel's registry test keeps passing.
* D2 One `DimensionNode` table + 4 proxy models (names from `kernel.dimensions`), composite FKs through generated
  constant columns so the DB also refuses cross-dimension references.
* D3 Hierarchy errors without a dedicated code (DETALLE parent, other-dimension parent) → `validation_failed` with
  pointer/reason; foreign/unknown parent → `dimension_cross_company` (no existence oracle). (CCR P05-4)
* D4 Rule precedence: priority, then FORBIDDEN > REQUIRED > ALLOWED; `concept` = `PostingRequest.purpose`;
  `stock_document` = document types `inventory.*`; rounding lines exempt from REQUIRED.
* D5 Archive/expiry blocks new references (`dimension_archived`); reversals of existing entries still copy archived slots.
* D6 Multi-currency: invariant 1 per currency for single-currency entries and always in COP; mixed-currency residual ≤
  tolerance → `FX_ROUNDING` line. COP conversion half-even to 4 decimals (shared/07 §8).
* D7 Soft-closed posting permission = `ledger.period.update` until a dedicated code exists (CCR P05-4).
* D8 AuditService is used when registered (P07); otherwise changes still emit outbox events. Policy is mandatory
  (`services.get(PolicyService)` fails closed).
* D9 Period row read with `FOR SHARE`: concurrent postings do not serialize; a close waits for in-flight postings.
* D10 T-ACC-DIM-08 is self-contained (starts Vite itself, contract fake of the dimension API) because demo users exist
  only after P21 (wave 8) and the Makefile runs Playwright without a config (CCR P05-2/P05-3).

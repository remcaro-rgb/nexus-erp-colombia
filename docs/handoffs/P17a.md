## What was built

### Backend `backend/documents/` (Django app, routes at `/api/v1/documents/`)

| Area | Files | Notes |
|---|---|---|
| PDF engine | `pdf/writer.py`, `pdf/fonts.py`, `pdf/reader.py` | Deterministic pure-Python PDF 1.4 (CCR P17a-1): standard-14 fonts (WinAnsi, Decimal metrics), grayscale image XObjects (zlib 9), no timestamps, `/ID` = SHA-256 of the content. `reader` parses what the writer produces (xref, page text from `Tj`, images) — used by the tests and available for integrity checks. |
| Template language | `markup.py` | Strict Jinja-like **sandbox**: `{{ path\|filter:arg }}`, `{% for %}`, `{% if %}/{% else %}`; paths walk plain JSON data only (dict keys / list indices, **never getattr**), names `[A-Za-z][A-Za-z0-9_]*` without `__`/leading `_`; no calls, operators or literals outside filter args → every SSTI escape fails at parse time. Whitelisted filters `upper lower money number words date default truncate join length`. Limits: 10,000 chars, nesting 16, 5,000 loop iterations, 200,000 output chars. Interpolated values are marked so data can never inject layout markup. |

## How to use it

```text
GET  /api/v1/reporting/semantic-model[?format=csv|xlsx|pdf]
POST /api/v1/reporting/query          {"parameters": {"entity": "ledger.journal_line", "measures": ["net_credit"],
      "dimensions": ["cost_center:root", "posting_date"], "time_grain": "month", "as_of": "2026-10-31",
      "filters": [{"field": "branch_id", "op": "eq", "value": "<uuid>"},
                  {"field": "cost_center", "op": "in_subtree", "value": ["<group id>", "<leaf id>"]}],
      "sort": [{"field": "net_credit", "dir": "desc"}], "limit": 100, "companies": ["<uuid>"]}}
POST /api/v1/reporting/query:explain  (same body) → {status, data: {sql (placeholders), estimate, interactive}}
POST /api/v1/reporting/reports {code, name, definition: {query, view}} · PATCH (If-Match) · DELETE (unused only)
POST /api/v1/reporting/reports/{id}:run | :publish | :archive | :schedule {"parameters": {"cron": "30 7 * * 1", "format": "pdf"}}
GET  /api/v1/kpis/reportes?period=YYYY-MM · /api/v1/kpis/reportes/panels/ejecuciones_diarias
POST /api/v1/documents/render {"parameters": {"source_type": "treasury.receipt", "source_id": "<uuid>"}} → application/pdf
POST /api/v1/documents/render {"parameters": {"template_code": "sales.quote", "data": {...}}}
POST /api/v1/documents/templates {code, name, document_type, body} · PATCH (If-Match) · :preview {"parameters": {"sample": {...}}}
POST /api/v1/documents/render:render-batch {"parameters": {"items": [{...}, ...]}} → 202 Operation
```

In code: `reporting.engine.run(ctx, [company_id], query)`, `services.get(ReportQueryService).run(ctx, ReportQuery(...))`,
`services.get(DocumentRenderer).render(code, data, watermark=...)`, `documents.service.render_source(uow, company, type, id)`.

## Decisions taken under ambiguity

1. **PDF engine** — pure-Python deterministic engine instead of WeasyPrint (not installable within owned paths; needs
   system libs). Contract `engine` value stays `weasyprint`. CCR P17a-1.
2. **Template language** — no Jinja2 dependency available; a strict Jinja-like subset with no Python evaluation at all
   (safer than a Jinja sandbox: there is nothing to escape to).
3. **Row policy in SQL** — the entity's `PolicyService.scope_queryset` is compiled by Django and embedded as
   `alias.id IN (subquery)`, so the semantic layer applies exactly the same row scope as the ORM paths (plus RLS).
4. **Hierarchy grouping** — `field:root` / `field:parent` modifiers over the effective-dated closure (`as_of` or
   current). Labels `<dim>__label` = `code — description`.
5. **Cache** — Django cache, TTL 120 s, key includes policy version, principal, companies and an entity freshness probe
   (count + max(created_at) of journal entries), so new postings and policy changes never serve stale results.
6. **Render batch** — rendered in the same request (≤ 200 items) and answered 202 with a finished `Operation`; the kernel
   `/api/v1/operations/{id}` route is not implemented yet (CCR P17a-3).
7. **Saved-report visibility** — owner, or published (+ `reporting.report.read`); `share_roles` stored but role
   filtering needs P04 support (CCR P17a-3). Managing others' reports needs `reporting.report.admin` (appended).
8. **`:run` permission** — contract `x-permission: reporting.report.update`; the run itself also needs the entity's read
   permission (engine).
9. **Generic template** — any template code without a built-in body renders the generic key/value layout, so modules
   already calling `DocumentRenderer` (sales portal, HR certificates, stock issues) get real PDFs.
10. **Watermarks** — default DEV label on every page; treasury documents use "SINTÉTICO — sin validez fiscal (DEV)".

## Known limits

* Not in P17a (owned by P17b/P17c): standard reports (`/standard/...`), exógena, certificates, cash-flow mapping.
* XLSX export is a minimal single-sheet workbook (no styles); PDF export of a result is a plain table.
* No DOCX (`[A]` item). Fonts are the standard-14 (WinAnsi) — glyphs outside cp1252 print as `?`.
* `reporting.report.read` users see published reports of the company; role-based sharing pending (CCR P17a-3).
* The scheduled delivery stores the run and emits the event; e-mail/in-app delivery of the file goes through P07
  notifications later (no real e-mail in DEV).

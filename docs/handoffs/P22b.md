## What was built
### Honest framing first
On `main` (d601cff) only kernel, IAM, ledger (P05), tax engine (P06), workflow/audit (P07) and `localization_co` exist. Inventory,
sales, purchasing, POS, payroll, assets, e-invoicing, treasury and onboarding are built in this wave or later. Every scenario
therefore has two kinds of tests:

* **reference legs** (PASS today): the scenario's documents are composed by P22 test doubles exactly as C1-1/C1-2 require —
  gap-free number from the real `kernel.sequences`, stock through a DB-backed `StockService` double, balanced entries through the
  **real P05 `PostingService`** (both books), outbox event and audit record through the **real** kernel UoW and P07
  `DbAuditService`, taxes from the **real P06 `TaxEngine`** with labelled FIX parameters. Every amount is checked against an
  independent Decimal oracle. These legs prove the ledger/tax/platform side and the composition rule; they do not claim the
  missing modules work. They carry **no UR marker** (traceability never over-claims).
* **module legs** (`test_*_module_leg_*`, XFAIL today): they call `defects.require("PEND-P09", …)`; while the owning Django app is
  not installed they report XFAIL with the pending module's id (never PASSED, never skipped); once installed they run for real.
  They carry the module URs (UR-08…UR-13, UR-18), so `traceability.py --check --gate G2` stays red until the modules deliver.

## Decisions taken under ambiguity
1. Reference doubles instead of waiting (decision default "code against the frozen contract / typed fake"): DB-backed, because the
   in-memory `FakeInventory` survives a rolled-back UoW and cannot prove atomicity.
2. Module legs use imperative `pytest.xfail` with a registered PENDING id (not skip — forbidden without BLK-, and not strict xfail
   — a strict marker would XPASS the moment a module lands without checking anything module-specific).
3. UR markers only on tests of real code (ledger, RLS, contract, oracle-vs-contract) and on module legs; none on reference legs.
4. Request-level sweeps inject a handled `DomainError` (500 problem+json) so the view is finalised; the unhandled path is DEF-P22-009.
5. S11 fixture pack lives in `tests/cross_module/fixtures/onboarding/andina/` as CSV (shared/11 names `tests/fixtures/…xlsx`;
   `tests/fixtures/` is not an owned path and openpyxl is not a dependency). Synthetic NITs; 5 wrong DVs on purpose.
6. FIX labour rules for S7 (night window 19:00 from 2025-12-25, Sunday surcharge 80/90/100 %, weekly max 44/42 h, divisor 210)
   are oracle data labelled NOT LEGALLY VERIFIED; they are not parameters of any module.
7. S6 withholding uses a FIX 25 % exempt simplification that only covers the 0 % bracket (the oracle refuses other inputs).

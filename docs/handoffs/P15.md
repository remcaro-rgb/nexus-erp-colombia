## What was built
* **Annex profile** (`einvoice/annex.py`): adopted versions (Res. 227/2025), code lists with provenance status
  (`OFFICIAL_FILE_PRIOR_VERSION` from the hashed DIAN v1.8 files, or `SYNTHETIC_NOT_LEGALLY_VERIFIED`); `require_verified` blocks production.
* **Hashes** (`einvoice/hashing.py`, `specs/fiscal-hash/`): CUFE, CUDE, ApplicationResponse CUDE (annex v1.8 worked examples reproduced),
  CUDS and CUNE (synthetic formula, labelled). Formulas are data; `formulas.json` is generated from them and tested for equality. Annex erratum documented.
* **Canonical model + builders** (`model.py`, `builders/`): `FiscalDocumentModel` (Decimal only, totals validated) → UBL 2.1 Invoice
  (FE 01/02/03/04, DEE POS, DS), CreditNote (NC, DS nota de ajuste), DebitNote, NominaIndividual(DeAjuste) (synthetic layout),
  ApplicationResponse (RADIAN), AttachedDocument. Pure, deterministic, versioned by annex version; golden files per type.
* **Signing** (`signing.py`): enveloped XML-DSig + XAdES SignedProperties (signing time, cert digest, DIAN policy v2 id, role) —
  `FIXTURE_NOT_CERTIFIED` HMAC-SHA256 key held only by the worker (CCR P15-1 for RSA). Independent re-verification detects tampering.
* **Adapters** (`adapters/`): `ProviderAdapter` protocol, `SandboxSimulator` (deterministic fixture switch, refuses production),
  `HttpProviderAdapter` (generic PT connector, `generic-json-v1` mapping + `register_mapping` hook, SANDBOX/https only, credentials only
  in `Authorization`, errors redacted), `DirectDianAdapter` `[A]` (registered, always fails closed), adapter **registry** (plug-in by key),
  and the reusable **contract suite** (11 cases) used by tests and `:test-connection`.
* **Lifecycle** (`lifecycle.py`): the prompt's state machine, append-only transition log, outbox event per transition, backoff.
* **Services/worker** (`service.py`, `worker.py`): registration inside the caller's UoW (no I/O), signing + transmission in the worker
  outside any UoW (outbox consumer `einvoice.transmit` + `process_due` sweeper + `manage.py einvoice_worker`), duplicate protection,
  automatic contingency after 3 consecutive transport failures, manual issuer contingency (type 03), 48 h deadline from restoration,

  rules and tacit acceptance after 3 business days (Bogotá calendar), certificate expiry alerts (30/15/7), habilitación runner.
* **Evidence** (`models.FiscalEvidence`, `crypto.py`): every XML (unsigned, signed, responses, events, ZIP) encrypted at rest, SHA-256,

## Known limitations, [A] items
* Signature is an HMAC fixture (no RSA/PKCS#12 library pinned) — CCR P15-1; DIAN would reject it. Evidence envelope uses stdlib
  primitives (encrypt-then-MAC with HMAC-SHA256) pending AES-GCM.
* No XSD validation (no validator pinned) — XSD hashes recorded; CCR P15-1. Root elements serialize with an `ns0:` prefix (stdlib limit).
* "MinIO with object lock" (T-P15-13 wording): evidence is stored in PostgreSQL with an append-only trigger and legal hold; there is no
  object-store adapter in P15's paths.
* Buyer e-mail is queued in the delivery log only (CCR P15-2); the PDF representation is P17's (QR URL/data are in the XML).
* Settings activation of a provider is per company (all families); per-family providers not modelled (contract has no family field).
* KPI `period_id` (ledger period id) is not resolved: `period=YYYY-MM` or the current month.
* `[A]` `DirectDianAdapter` registered but fails closed (flag `einvoice_direct_dian`, off); RADIAN endorsement/factoring not built; no TS hash port.

## Decisions taken under ambiguity
1. Production can never transmit in this edition: `FISCAL_MODE=production` refuses the simulator and any transmission (even with gate records).
2. Contingency: a DIAN/PT outage keeps type 01 and is transmitted late; an issuer-side outage (manual) switches new FE to type 03.
   Automatic switch after 3 consecutive transport failures (no admin-alert channel without CCR P15-2; the declaration is audited).
3. A REJECTED document is final (no retry): correct it with a note or a new document; numbers are never re-issued.
4. Provider switch = two different administrators (`PUT /settings` twice); first activation needs one. Changing the connection of the
   ACTIVE provider is refused (register a new provider and switch); any connection change resets a provider to DRAFT (re-test).
5. External actions (`:test-connection`, `:sync`, `:run`) run their external part outside the unit of work, then record the result in an
   idempotent command; a replayed key skips the external part.
6. Received supplier invoices are registered with `register_received_document` (family `FE_RECEIVED`) so buyer-side RADIAN events can reference them.

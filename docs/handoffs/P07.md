* T-FORMULA-ENGINE-02 `test_formula_adversarial.py` — 150+ adversarial expressions (imports, builtins, attribute/dunder access, lambda, comprehensions, huge exponents/magnitudes, deep nesting, long strings, unicode tricks incl. homoglyphs/zero-width/bidi, type confusion), recursion via dependencies, schema-name sanitizing and an AST static scan of all workflow code.
* T-FORMULA-ENGINE-03 `test_formula_budget.py` — node-visit and CPU budgets (injected clock and real thread clock), static budgets (chars, nodes, nesting, graph size), budgets only tighten, worst admitted formula < 50 ms CPU, 8 hostile threads do not starve a normal evaluation.
* T-FORMULA-ENGINE-04 `test_formula_graph.py` — cycle detection with the cycle path (self, 2-, 3-, inner cycles, 200-chain back edge), deterministic topological order (Kahn, sorted ties), typed dependency results, closure evaluation.
* T-FORMULA-ENGINE-05 `test_formula_exfiltration.py` (+ `test_formula_lifecycle.py::test_T_FORMULA_ENGINE_05_db_tables…`) — undeclared/system table names, malformed and dynamic table names, cross-company and cross-tenant tables (no existence oracle), undeclared inputs.

## Decisions taken under ambiguity
1. **App installation without touching settings.** `erp/settings` and `erp/urls` belong to P01; `tests/conftest.py` installs `workflow` at collection time so migrations + DB tests run in `make ci` (no-op once CCR P07-1 is applied). Routes are mounted in tests through `workflow/tests/urls.py`.
2. **D-008 limits** are hard maxima; `Limits` may only tighten them. Expression length uses D-008 (4,000) although the dataio column allows 10,000. Numbers: no exponent notation, ≤ 40 digits, |value| < 10³⁰; strings ≤ 1,000 chars; round places −9…12.
3. **Grammar choices:** `==`/`!=`/`<>` for equality (single `=` is an error), no chained comparisons, `and/or/not` keywords (short-circuit), no string concatenation, names are case-sensitive, functions case-insensitive. Extra functions beyond the addendum: `day`, `date('YYYY-MM-DD')`, `add_days`. `lookup(table, key[, default])` with a literal table name declared in the schema.
4. **Default rounding:** `round(x, n)` uses HALF_UP; result types money/quantity/percent quantize to 4/6/6 places half-even (C2-2) unless `output_places`/`output_rounding` are set.
5. **Condition errors in approval policies match** (fail safe: ask for approval rather than skip it).
6. **One live approval request per document + action** (idempotent `request`).
7. **Formula status mapping** to the frozen contract: PENDING_APPROVAL→SUBMITTED, ACTIVE→APPROVED (CCR P07-3 §3).
8. **Field masks are deny-by-default:** without a readable mask the approval amount and audit `ip`/`user_agent` are null and audit `changes` show only `{"changed": true}`.
9. **Webhook targets are restricted to local/test hosts** in this DEV-only build (`production_endpoint_refused`), which also limits SSRF.
10. **DSR terms** (10+5, 15+8 business days) are the statutory terms of Ley 1581 arts. 14–15 named in the pack (S-24); the holiday calendar is never invented (P06 input, fixture in tests).

## Known limits / not done here
* No RLS policies are created by P07 migrations (P04 owns final policies; table list in CCR P07-2 §5). Application code always filters by tenant/company.
* The DEV file store is a local directory (mode 0600); server-side encryption is a property of the MinIO bucket in the dev stack (not exercised in tests). ClamAV `[A]` is not wired (scan hook + EICAR detector only).
* WebSocket/SSE push for notifications is not implemented; the bell polls `GET /notifications` (`unread_count`). WhatsApp/SMS `[A]` adapters are off.
* API endpoints not implemented yet: approval-policies CRUD, attachments (`/attachments`, `:presign`, `/content`) and dsr-requests HTTP endpoints — the services exist and are tested (`AttachmentService`, `DsrService`, policies via the ORM); only the HTTP layer is missing.
* The frontend has no pages yet beyond descriptor/client/helpers (P08 provides the shell and FormulaEditor; the vitest file runs once `frontend/package.json` exists).
* `docs/modules/workflow.md` is outside P07's paths; this handoff is the module guide.

## How to use
```python
from workflow.formula import FormulaDefinition, FormulaGraph, InputSchema
d = FormulaDefinition("iva", "round(base * 0.19, 2)", InputSchema.from_json({"base": "money"}), "money")
FormulaGraph([d]).evaluate({"base": "1000"})["iva"].value   # Decimal('190.0000')
```
* Modules: `DbWorkflowService().require_approved(uow, company, DocumentRef(...), "post", facts)` before posting;
  `services.get(AuditService).record(uow, AuditEntry(...))` or `workflow.audit.service.record_change(...)` inside the UoW.
* `python manage.py audit_verify [--tenant UUID]` verifies the chain (non-zero exit on tampering).
* Tests: `make test-ids IDS="T-FORMULA-ENGINE-01 T-FORMULA-ENGINE-02 T-FORMULA-ENGINE-03 T-FORMULA-ENGINE-04 T-FORMULA-ENGINE-05"`; all workflow tests: `uv run --frozen pytest backend/workflow`.

## Decisions taken under ambiguity
* **P03-D1 two compose layers**: `deploy/dev/compose.yaml` is the single definition (D-P03 runtime, no `build:`); the root
  `docker-compose*.yml` (ADR-014) reuse it via `extends` and add `build:`. Avoids duplicated service definitions.
* **P03-D2 wave-aware stack**: profiles `app`/`web`/`mcp` are enabled only when the images exist; app services start only when
  their code exists (celery locked, management command present). Missing parts are reported as `not_available_yet`, never faked.
  dev-up builds images itself when sources exist (D-P03 says images are built by RC; dev-up needs them earlier).
* **P03-D3 MinIO image**: upstream `minio/minio` is no longer on Docker Hub (pull denied, 2026-11-09); using
  `docker.io/pgsty/minio` (community build of the MinIO server, AGPL — dev/staging service only, not linked into the app).
* **P03-D4 Keycloak start-dev with dev-file DB** on the `keycloak-data` volume (simplest for DEV); prod overlay uses
  `start --optimized` + PostgreSQL.
* **P03-D5 internal `backend` network**: every service except the proxy has no internet egress — enforces "no live external
  effects" (D-ALL 2) at the network level.
* **P03-D6 gen-secrets appends missing keys** to an existing file (never overwrites existing values) so new services get
  secrets without regenerating old ones; D-P03 "only if the file does not exist" is kept for every existing value.
* **P03-D7 builds behind the session egress proxy**: `build-images.sh` uses `--network host`, proxy build args and the
  proxy CA as a BuildKit secret (nothing persisted in layers). Needed in cloud VMs; inactive elsewhere.
* **P03-D8 dev-up starts dockerd** when the daemon is not running and passwordless sudo exists (cloud VMs).
* **P03-D9 P03 tests live in `scripts/ci/tests/`** (owned path), stdlib + pytest-compatible, Docker required (they fail,
  never skip, without Docker).
* **P03-D10 PII patterns scrub only free-text OTel attributes** so `trace_id`/`tenant_id`/`company_id` stay intact.
* Mailpit UI and Grafana are routed through the proxy with authentication (dev convenience, loopback only).

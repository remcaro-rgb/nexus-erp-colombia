## Decisions taken under ambiguity
1. Generated contracts from compact sources (`contracts/src/`) so 1,221 operations follow the conventions uniformly; generated files are committed and checked.
2. Registry names win over prompt examples: `stock_insufficient` (not `insufficient_stock`); FEATURES-ADDENDUM paths kept verbatim (CCR-P02-4).
3. Events are part of the frozen OpenAPI as 3.1 `webhooks` (one per event type) + standalone JSON Schemas; each FEATURES-ADDENDUM feature with state transitions
   publishes ≥ 1 event (none are named in the registry itself, so the event names are P02's, following `<module>.<entity>.<verb>.v1`).
4. GET is allowed only for read-only actions `:export` and `:comparison` (the registry specifies `GET …:export`); all other actions are POST.
5. Secret references (`*_ref`, uploads) are writeOnly and appear only in request bodies — never in a read model (stronger than "never returned").
6. Portal API carries no X-Company-Id; scope comes from the token (D-033). MCP has no own REST surface; its scopes are module read permissions.
7. Bundled JSON twin (`openapi.json`) is the machine input (fast, no YAML dependency in tools); YAML stays the human/mock format; a test proves they are equal.

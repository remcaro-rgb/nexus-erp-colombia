Decisions taken under ambiguity (with rationale):
* D-P04-1: JWT RS256 implemented with the standard library (no JOSE library in `uv.lock`, which P01 owns); strict RS256-only, full EMSA-PKCS1-v1_5 re-encoding compared in constant time, ≥ 2048-bit keys.
* D-P04-2: Invitation acceptance = the invited person sets the password in Keycloak, logs in through `erp-portal`, then `POST /api/portal/v1/invitations:accept {token}` links that subject (CCR P04-2). Tokens are only sent inside the notification request (local mail capture), stored hashed.
* D-P04-3: Revoked/suspended portal accounts get `401 unauthenticated` (the identity is no longer valid for the ERP); portal requests naming another party/company get `403 external_account_scope_violation`; foreign ids → 404.
* D-P04-4: The first active branch of a company must be created as head office (`branch_head_office_required`); promoting another branch demotes the previous one in the same transaction; a deferred constraint trigger re-checks "exactly one" at commit.
* D-P04-5: A scope restricts only resources that carry the scoped attribute; the bound company is the `X-Company-Id` (or default membership) — one company per request.
* D-P04-6: External users are `iam_user` rows of kind EXTERNAL; a DB trigger forbids any role assignment to them.
* D-P04-7: RLS for kernel tables deferred to P01 (CCR P04-4) to avoid making kernel unit tests depend on IAM.

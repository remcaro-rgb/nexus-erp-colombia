Decisions taken under ambiguity (with rationale):
* UoW API: the prompt names a context manager that also retries; a `with` block cannot re-run its body, so
  `unit_of_work()` is the single-attempt context manager and `run_in_unit_of_work(fn, ctx, ...)` / `@transactional` add
  the retry loop. Nested UoWs join the outer one; nested idempotency keys are refused.
* Idempotency record is inserted in the command's own transaction (no IN_PROGRESS state visible): concurrent same-key
  requests block on the unique index and replay after commit; a failed command releases the key. Replays without an explicit
  response return status 204 / body null.
* Test DB access: peer auth over the unix socket with a role named after the OS user (no password anywhere);
  `make db-setup` creates it non-superuser. Chosen over a generated password file to avoid writing secrets.
* `ERP_ENVIRONMENT` accepts only `dev` and `test` (D-ALL 1); any other value refuses to boot.
* Kernel outbox/inbox/dead-letter tables are treated as platform tables (relay role); kernel tenant tables need P04 RLS (CCR P01-5).
* Dimension FK target model names are P01's guess for P05 (CCR P01-5).
* Fixtures live in `kernel.testing.fakes` (not `kernel/interfaces/fakes`) to keep the interface package import-light.
* mypy is strict for kernel library code; tests are linted by ruff and executed but excluded from type checking.
* Hypothesis on-disk database disabled (no `.hypothesis/` in the tree; `.gitignore` is protected); coverage data in `reports/`.

# DECISIONS-DEFAULTS — fixed defaults so agents never need to ask (2.2.0-dev)

Binding with FEATURES-ADDENDUM (CCR-FEAT-001). An agent that meets a missing design detail picks the documented default, or — if none applies — the most
restrictive safe choice, records it as an ADR in its handoff (`docs/handoffs/<Pxx>.md` § Decisions) and continues. M5 reviews it at the next gate (CCR if it
changes a contract). Never ask the operator for routine product decisions. Never choose anything that weakens security, isolation, ledger atomicity or dev-only rules.

| ID | Topic | Default |
|---|---|---|
| D-001 | Locale and money | UI language es-CO; timezone America/Bogota; functional currency COP; other currencies enabled per company (ISO 4217) with daily rates; amounts NUMERIC(20,4), unit prices/costs NUMERIC(20,6), quantities NUMERIC(20,6); Python Decimal only (no float anywhere); document totals rounded ROUND_HALF_UP to the currency minor unit (COP 2) and rounding differences posted to the configured rounding account. |
| D-002 | Dev port | M5 binds 127.0.0.1 only. Preferred port 8080; if busy, the first free port of 8081…8090 (loopback) found by the preflight is selected with the `dev_port_select` event; origin, OIDC redirect URIs and health URLs are derived from the selected port. All 11 busy → BLOCKED_DEV_RUNTIME with the list of busy ports. Never 0.0.0.0, never killing a process. |
| D-003 | Charts | Chart.js (the library used by the reference HTML), installed from the npm registry by P08 into package.json and pinned to one exact version in pnpm-lock.yaml at implementation time; bundled locally, never loaded from a CDN; animation off in visual tests. |
| D-004 | Barcodes | Internal codes use Code 128 (subset auto) with value `<company_code>-<8-digit sequence>`. EAN-13 is generated only from a company GS1 prefix entered by a user; the synthetic demo uses restricted-circulation prefix 20–29 labelled 'uso interno, no licencia GS1'. Imported GTINs are validated (mod-10) but never claimed as owned. Encoders are pure Python in P09 (no network, no external service). |
| D-005 | Documents and labels | All printable documents (labels, recibos de caja, comprobantes de egreso, portal downloads) are rendered by the `kernel.interfaces.DocumentRenderer` contract frozen at G0 and implemented by P17 with WeasyPrint (exact version pinned in uv.lock). Before P17 is accepted, modules test against the contract test double; G3 proves real PDFs. |
| D-006 | Cash-flow method | Estado de flujos de efectivo defaults to the indirect method (as P17 already states); the account→cash-flow-line mapping ships with the synthetic PUC seed and is editable. |
| D-007 | Dimension depth | Default maximum depth 6 (allowed 1–10) for cost centers, business units, auxiliares abiertos and ítems contables. |
| D-008 | Formula sandbox limits | Expression ≤ 4,000 characters, ≤ 500 AST nodes, nesting ≤ 32, ≤ 200 formulas in one dependency graph, evaluation budget 10,000 node visits and 50 ms CPU per formula, Decimal context precision 28, no loops/recursion/attribute access/imports/IO. |
| D-009 | Quotation scoring | Score = 60 normalized landed price + 20 lead time + 10 vendor rating + 10 payment terms (weights editable per company, sum 100). Ties: lower landed COP total, then earlier quote receipt, then vendor code ascending. The recommendation is explainable (per-criterion values) and never awards by itself. |
| D-010 | RFQ defaults | Response deadline 5 business days (Bogotá calendar); at least 1 invited vendor, 3 recommended (warning only); late quotes are stored as LATE and excluded from scoring unless a buyer reopens the RFQ with a reason. |
| D-011 | Automatic drafts and spend limits | An approved internal requisition remainder creates a DRAFT purchase requisition/PO only when a valid vendor price (award or price agreement ≤ 90 days old) exists and the line total ≤ company threshold (default COP 5,000,000). Drafts always enter the normal approval workflow; nothing is sent to vendors automatically; AI proposals are never auto-confirmed. |
| D-012 | Automatic transfers | Same company only. Source warehouse order: configured priority list, then highest available quantity, then warehouse code. Creates a DRAFT transfer with reservations; shipping and receipt are confirmed by warehouse users (in-transit location between). |
| D-013 | Presentations | Canonical stock is kept in the item's base UoM. A presentation (e.g. bolsa 500 g, caja x12) is a packaging identity with an exact factor to the base UoM, its own barcode and precision. Packaged quantities are a sub-ledger of the canonical quant (Σ packaged × factor ≤ canonical), so stock is never counted twice. |
| D-014 | Locations | Each warehouse gets a root VIEW location and default bins RECEPCION, ALMACEN, DESPACHO, TRANSITO, SCRAP. Stock posts to leaf INTERNAL bins only. Default putaway: item default bin in that warehouse, else RECEPCION. |
| D-015 | Portioning tolerance | Actual output weights are captured; the default yield tolerance is ±2 % against the template; outside tolerance needs an approval with a reason. |
| D-016 | Transformation costing | Output cost = consumed input cost + recorded additional costs. Allocation by the template's cost-share %, else by relative standard value; rounding remainder to the main output. Normal waste is absorbed into outputs; abnormal waste (beyond tolerance) is expensed to the configured account. Value in = value out (+ expensed waste) exactly. |
| D-017 | Treasury numbering | kernel.sequences codes `RC` (recibo de caja) and `CE` (comprobante de egreso) per company with a configurable prefix; gap-free; voiding is a reversal document and numbers are never reused. |
| D-018 | Portal identities | Keycloak realm (P04 template) gets client `erp-portal` and groups portal-supplier, portal-customer, portal-employee. External users are linked to exactly one party/employee and one company. Dev demo accounts and their random passwords are generated by the seed into the mode-0600 secrets file on M5; invitations go to the local mail capture (Mailpit). No SMS, no real e-mail. |
| D-019 | Exógena data | The engine ships with one synthetic format pack `SYN-EXO-1001` (clearly labelled 'SINTÉTICO — no válido ante la DIAN'). Real yearly DIAN format packs are an external legal input (blocker B-14); they are imported later as data and never invented. Dev completion does not require them. |
| D-020 | AI provider | Default is the deterministic local fixture adapter, visibly labelled 'IA en modo de prueba (sin proveedor conectado)'. A real provider is used only if the operator configured credentials on M5; its absence never blocks DEV. |
| D-021 | Customer payment intents | The customer portal creates payment intents against a simulated provider (FIXTURE_NOT_CERTIFIED); a simulated success never posts by itself — treasury confirms and creates the recibo de caja. |
| D-022 | Visual baselines | M5 derives the first baselines at G1 (shell) and G4 (all screens) from the running build, compares them with the reference measurements (UI-CONTRACT §9), and approves each baseline once with a recorded reason. Regressions are never silenced by regenerating baselines; accessibility exceptions are listed with a reason in docs/gates/G4.md. |
| D-023 | Approvals in dev tests | E2E tests use seeded synthetic approver accounts with the right roles; segregation of duties is still enforced (the requester never approves). |
| D-024 | Price precedence | Manual override (approval if above the user's discount limit) > active price formula > price list > item base price. Posted documents are never repriced; re-pricing applies only to drafts and shows a diff. |
| D-025 | Payroll formula order | Concepts are evaluated in topological order of their declared dependencies within a period version; cycles are rejected on save; legal parameters come from versioned parameter tables (fixture values in dev, marked NOT LEGALLY VERIFIED). |
| D-026 | Run id | M5 generates `erp-dev-YYYYMMDD-xxxx` (UTC date, 4 hex from os.urandom) when no compatible non-terminal run exists on the remote and none is pinned; workers discover it; ambiguity stops with a named reason. |
| D-027 | Polling | Idle machines poll with backoff 1, 2, 4, 8, 15, 15… minutes; any control-state change resets the backoff; a session stops idle only after 6 h without any control progress (seq unchanged). |
| D-028 | Versions | Stack per the frozen architecture (Django + DRF, React + TypeScript, PostgreSQL, Python 3.13, Node 22). Every dependency is pinned exactly in uv.lock / pnpm-lock.yaml when first added; container images pinned by digest at RC; no `latest` tags; install scripts verify lockfile hashes. |
| D-029 | Withholdings on treasury documents | Computed by the P06 tax engine from the party tax profile and concept; unknown parameters fail closed with `tax_parameter_unknown`; users may only override with permission and a reason (audited). |
| D-030 | Business-unit defaults | Business units are an independent master; a branch may declare a default business unit that pre-fills document lines; the dimension rule matrix decides required/allowed. |
| D-031 | Requisition consolidation | Consolidation groups APPROVED requisition lines by company + item + presentation + needed-by week + delivery warehouse; lineage keeps every source line id and quantity; a consolidated line never exceeds the sum of its sources. |
| D-032 | Stock negatives | Negative stock is disallowed by default (warehouse flag `allow_negative` stays false in the seed); every stock-consuming action checks availability under row lock in the same transaction. |
| D-033 | Portal session | Portal sessions: OIDC code flow + PKCE, 30 min idle timeout, 8 h maximum; external users cannot obtain internal roles; every portal API call carries the party scope from the token, never from the request body. |
| D-034 | Feature-complete definition | The run may reach DEV_RUNNING only when every check in features/feature-registry.json is PASSED in the DEV evidence (unit, integration, UI, visual, a11y, portal logins, print smoke) on the exact RC commit and images. |

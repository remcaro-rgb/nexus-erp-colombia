# CCR P16a-3 — seed / tenant data the treasury postings and approvals need (P21, P05, P04, P07)

* From: P16a · To: P21 (seed), P05 (ledger), P04 (roles), P07 (approval policies) · Type: data · Status: OPEN
* **Control accounts**: AR (role `AR`) must list `treasury.` in `control_sources` (besides `sales.`) and AP (role `AP`)
  `treasury.` (besides `purchasing.`); otherwise the ledger refuses RC/CE postings (`account_not_postable`).
* **Account roles** used by treasury: `CUSTOMER_ADVANCE`, `VENDOR_ADVANCE`, `WHT_RECEIVABLE`, `WHT_PAYABLE`, plus the
  roles named by each `TreasuryConcept.account_role` (e.g. `LOAN_PAYABLE`, `REIMBURSEMENT`, `CAPITAL`, `EXPENSE`).
  The fund's money account is the ledger `Account` of its bank account / cash box (`account_id`).
* **Approval policies** (P07 `workflow_approval_policy`, synthetic): `TES-RC` (receipts at or above
  `rc_approval_threshold`), `TES-CE` (disbursements / batches at or above `ce_approval_threshold`, default 0 = always),
  `TES-DUAL` (disbursements / batches at or above `dual_approval_threshold`, default COP 20,000,000; **quorum 2**). A
  missing policy fails closed with `treasury_approval_required`.
* **Sequences** (D-017): `RC` / `CE` with the company prefix (`RC-` / `CE-` default) and `TES-LP` / `LP-` (payment
  batches) are created on first use or by `treasury.services.common.configure`.
* **Roles (P04)**: cashier = `treasury.receipt.*`, `treasury.disbursement.*` without `approve`; approver =
  `treasury.*.approve` + `workflow.approval.approve`; registry permissions `treasury.read`, `treasury.reconcile`,
  `treasury.pay` and the new catalog code `treasury.kpi.read` (dashboard).

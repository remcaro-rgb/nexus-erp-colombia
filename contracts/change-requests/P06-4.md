# CCR P06-4 — notes for IAM (P04) and the UX shell (P08)

* From: P06 · To: P04, P08 · Type: integration notes · Status: OPEN

P04 (RLS / policy):
* Tenant tables with **nullable** `company_id` (NULL = tenant-wide row): `tax_parameter`, `tax_exogena_format_pack`;
  tenant table without company: `tax_source` (`tenant_id` NULL = platform register entry), `tax_parameter_approval`
  (append-only trigger installed by P06 migration 0002).
* Company-scoped tables: `tax_tax_code`, `tax_withholding_concept`, `tax_ica_tariff`, `tax_party_tax_profile`,
  `tax_calendar`, `localization_co_holiday_override` → composite FK `(tenant_id, company_id) → iam_company`
  (`kernel.db.company_fk_sql`) and RLS once `iam_company` exists.
* Platform reference data readable by every tenant: `localization_co_department`, `localization_co_municipality`,
  `localization_co_code_list_version`.
* `PolicyService.scope_queryset` is applied by P06 to company rows only (tenant-wide rows are filtered by tenant);
  please keep `scope_queryset` row-filtering semantics (it must not drop rows with `company_id IS NULL` if applied to them).

P08 (shell):
* P06 contributes the submenu Contabilidad › Impuestos through `frontend/src/features/tax/contribution.ts`
  (`registerTaxContribution(api)` with `api.contributeSubmenu(submenu)`); please expose a contribution API with that
  shape (or tell P06 the real one) and call P06's registration at startup.
* `frontend/src/features/tax/__tests__/model.test.ts` uses vitest; it runs once `package.json` / vitest exist.

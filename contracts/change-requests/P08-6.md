# CCR P08-6 — SPA sign-in: OIDC auth-code + PKCE against `erp-web`, bearer header, 401 → sign-in (OPEN, P08 + P01/P04)

Raised by: P08 attempt 3 · Owners: P08 (frontend, `frontend/src/lib/**`, `frontend/src/app/**`), P04 (identity/OIDC,
`/api/v1/ui/context`), P01 (platform/kernel tenancy, routes) · Found by: wave-02 UI preview (`login form not found`).

## Problem
The shell boots by calling `/api/v1/ui/context` through `frontend/src/lib/api/client.ts` with `credentials: "same-origin"`
and **no `Authorization` header**. The DEV backend is bearer-only, so the call returns 401 and the shell renders `BootError`
(`frontend/src/app/Boot.tsx`: "No fue posible cargar su contexto de trabajo…"). Nothing starts an OIDC login, so the
Keycloak login form is never reached.

## Requested change — frontend (P08)
* OIDC Authorization Code + PKCE (S256) against the public Keycloak client **`erp-web`**, issuer
  `<origin>/auth/realms/erp-dev` (DEV-ADDENDUM); discovery via `/.well-known/openid-configuration`; `state` + `nonce` checked.
* Callback route (e.g. `/auth/callback`) that exchanges the code, stores tokens **in memory** (refresh token in memory /
  sessionStorage only, never localStorage), and returns to the originally requested route.
* API client adds `Authorization: Bearer <access_token>`; refresh shortly before expiry; on **401** → silent refresh once,
  then redirect to sign-in preserving the return URL; `BootError` only for non-auth failures.
* Logout: clear client cache + tokens, then RP-initiated logout via the `end_session_endpoint`
  (`id_token_hint`, `post_logout_redirect_uri`) instead of `/ui/context.logout_url` fallback.
* Tests: unit tests with a fake IdP (PKCE verifier/challenge, state mismatch rejected, 401 → redirect) and a Playwright
  smoke against the DEV stack that reaches the Keycloak login form.

## Requested change — backend (P04 / P01)
* `/api/v1/ui/context` currently reads `tenancy.current()`; it must resolve tenant/company from the validated bearer token
  (claims or user membership) for a fresh session, and answer 401 (not 500) without a token.
* `/api/v1/ui/modules` does not exist yet (see CCR P08-1): implement it (registry filtered by the caller's permissions).
* Keycloak realm `erp-dev`: client `erp-web` redirect URIs / web origins / post-logout redirect URIs must include the DEV
  origin (`http://127.0.0.1:${ERP_DEV_PORT:-8080}` and fallbacks 8081–8090).

## Acceptance
The wave UI preview finds the login form, signs in with a seeded DEV user (secrets file only) and reaches `/m/inicio`.

# CCR P12-1 — additive POS contract fields/routes, consumers of the POS events, docs page

* From: P12 · To: contracts owner (integrator), P15, P04/P02 (roles), docs owner · Type: additive (nothing removed or retyped) · Status: OPEN
* Why: the generated `contracts/openapi/modules/pos.yaml` uses the generic schemas (`additionalProperties: false`). The
  F-ACC-BRANCH contribution (`PosConfig.branch_id` required, T-ACC-BRANCH-04), presentation scanning (F-INV-PRES /
  F-INV-BARCODE) and the ADR-015 checkout need the fields below. The implementation keeps every contract field and ADDS
  these; validators enforcing `additionalProperties: false` on responses need them in `contracts/src/modules/pos.yaml`
  and the module regenerated.

## `contracts/src/modules/pos.yaml`
1. `PosConfig` (+Input/Patch): **`branch_id` (uuid, required on create, internal)** — same company (composite FK →
   `iam_branch`, errors `branch_cross_company`, `BRANCH_ARCHIVED`); `location_id` (POS bin, nullable), `allowed_tenders`
   (array of CASH|CARD|TRANSFER|QR|VOUCHER), `receipt_profile` (object), `cash_limit` (Money, **confidential**),
   `blind_count` (bool), `default_party_id` (uuid|null).
2. `PosTerminal`: `registered_at` (date-time, ro). `:register` ActionRequest `parameters.device_key` (16–512 chars; only
   its SHA-256 fingerprint is stored).
3. `PosSession`: `number`, `config_id`, `cashier_id`, `business_date`, `blind`, `expected_cash`, `expected`, `counted`,
   `deposit_amount` (**confidential**), `journal_entry_ids`. `:open` ActionRequest `parameters{terminal_id, opening_cash}`;
   `:close` `parameters{counted{tender: amount} | counted_cash | denominations{face: count}, deposit_amount?}`.
4. `PosTicket`: `client_uuid` (= Idempotency-Key of the checkout), `cashier_id`, `branch_id`, `warehouse_id`, `subtotal`,
   `tax_total`, `change_due`, `cost_total` (**confidential**), `fiscal_doc_type` (DEE_POS|FE), `fiscal_status`, `cude`
   (from P15 `FiscalDocuments`, ro), `journal_entry_id`, `draft` (DRAFT only), `watermark` ("BORRADOR – sin valor
   fiscal" on DRAFT), `invoice_request` (**restricted-pii**). `status` uses DRAFT | POSTED | CANCELLED of the enum.
   Line: `presentation_id`, `barcode` (input: a scan resolves item/presentation server-side), `factor`, `base_qty`,
   `discount_pct`, `tax_amount`, `price_source`, `cost_value` / `unit_cost` (**confidential**, resource `pos.ticket_line`).
5. `tickets:checkout` ActionRequest `parameters{client_uuid, session_id, ticket_id? (parked draft), lines[{barcode |
   item_id[, presentation_id], quantity, discount_pct?, unit_price? (draft price, for the diff only)}],
   payments[{type, amount|tendered, reference? (required for CARD)}], party?, expected_total?, notes?}` →
   `ActionResult{status: POSTED, resource{type: pos.ticket, id, number}, data: PosTicket}`. New error codes:
   `pos_price_changed` (409; `errors.server` = recomputed cart incl. `total` and `diff[]`), `pos_tender_mismatch` (422),
   `pos_tender_not_allowed` (422), `pos_session_not_open` (409), `pos_session_already_open` (409),
   `pos_return_exceeds_sold` (422), `pos_offline_fiscal_selling_refused` (409). Existing codes reused:
   `numbering_range_missing`, `pricing_override_requires_approval`, `barcode_unknown`, `stock_insufficient`.
6. New route `POST /tickets:preview` (permission `pos.ticket.create`): server recomputation of a cart, persists nothing.
7. `tickets/{id}:to-invoice` `parameters.buyer{id_type, id_number, dv?, name, email, address?, municipality_code?, phone?,
   tax_regime?}` (R-FE-03 minimum: id_type, id_number, name, email).
8. `PosReturn`: `session_id`, `refund_tender`, `reason`, `subtotal`, `tax_total`, `cost_total` (**confidential**),
   `journal_entry_id`; line input `{line_no (of the original ticket), quantity}`. `CashMovement`: `number`, `journal_entry_id`.
9. `GET /catalog-snapshot?config_id=&since=` rows `{id, code, name, category, uom, gtin, tax_code, price, presentations[]}`;
   ETag + `If-None-Match` → 304.

## Permissions / roles
* Appended `pos.kpi.read` (source P12) to `contracts/permissions/catalog.yaml` (registry KPI code; P04's nav rule 4 resolves it).
  Please grant it in `contracts/src/roles.yaml` to a POS supervisor / gerente template. There is no POS supervisor role

## Consumers (P15 / P17)
* P15: consume `pos.ticket.checked_out.v1` (payload `ticket_id, number, total, journal_entry_id`) to build/transmit the
  DEE POS (family `DEE_POS`; source document `pos.ticket`), handle DIAN/PT outages with its contingency flow (R-FE-05,
  48 h timer — not owned by P12), expose the CUDE through `FiscalDocuments.status(DocumentRef("pos.ticket", id, number))`
  (P12 displays it on the ticket/receipt), and issue the FE for rows of `pos_invoice_request` (annex rule whether the
  issued DEE needs an annulment note: B-06). Returns are internal documents (`DVP-` numbers) and emit no fiscal event yet;
  the POS credit note (nota crédito del DEE) needs a P15 family — please add an event `pos.return.posted.v1` to the source.

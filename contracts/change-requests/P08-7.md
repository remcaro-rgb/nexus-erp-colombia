# CCR P08-7 — `erp-web` image fails CI image-scan: critical zlib in the Caddy alpine base (OPEN, to P03 / integrator)

Raised by: P08 attempt 3 · Target: P03 (`deploy/docker/frontend.Dockerfile`, not a P08 path).

## Problem
GitHub CI job "T-P03-01 docker compose up healthy from a clean clone", step `ci-parity.sh compose-startup --step image-scan`
(`cs_sbom`: grype `--fail-on critical --only-fixed` over every `erp-*` image) fails on the PR merge of P08
(run 42739215527, job 129575844892):
```
zlib                           1.3.2-r1   1.4-r0    apk        CVE-2026-4738  Critical
golang.org/x/net               v0.60.0    0.62.0    go-module  GO-2026-6860   High
github.com/klauspost/compress  v1.20.1    1.20.2    go-module  GO-2026-6865   High
[0102] ERROR discovered vulnerabilities at or above the severity threshold
CI-PARITY compose-startup exit=2
```
Reproduced locally with the pinned grype image: the findings are in **`erp-web:dev`** only (the base layer
`caddy:2.11.9-alpine@sha256:0bbb05…`); `erp-api:dev` has no critical. main never failed this step because
`scripts/ci/build-images.sh` builds `erp-web` only once root `package.json` + `pnpm-lock.yaml` exist, which P08 adds.
`tools/parity_gate.py` does not run the `image-scan` step, so the integrator's local gate is green (4/4) while GitHub CI is red.
Nothing in the P08 paths (the static `frontend/dist` copied into `/srv`) contributes to these findings.

## Requested change (P03)
In the `web` stage of `deploy/docker/frontend.Dockerfile`, either
* bump `CADDY_IMAGE` to a Caddy alpine digest whose zlib is ≥ 1.4-r0 (and Go deps rebuilt), or
* add `RUN apk upgrade --no-cache zlib` (as root, before `USER 10001:10001`).
Apply the same to the `proxy` service image in the compose file for consistency (not scanned today).
Acceptance: `bash scripts/ci/ci-parity.sh compose-startup --step image-scan` exits 0 on the P08 merge.

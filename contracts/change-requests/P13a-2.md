# CCR P13a-2 — contract additions for HR, time keeping and the employee portal

* From: P13a · To: integrator (owner of `contracts/src/**`; `contracts/openapi/modules/*.yaml` are generated, so P13a did
  not edit them) · Type: additive · Status: OPEN
* Implemented and tested now (routes marked "CCR P13a-2" in the code):
  1. `GET /api/portal/v1/employee/kpis` (permission `portal.employee_profile.read`, `x-portal: employee`) → the portal
     dashboard KPIs `ep_dias_vacaciones`, `ep_ultimo_pago`, `ep_solicitudes_pendientes` in the module-registry KPI format
     `{as_of, kpis:[{id,value,previous,delta,unit,state,formula_ref}], generated_at, portal}`. The P08 portal shell calls
     `GET /api/portal/v1/kpis?portal=<kind>`; P08/P04 may instead dispatch that generic route per portal kind to a
     provider registry — P13a's provider is `hr.portal.kpis.employee_kpis(view, employee)`.
  2. HR review of portal data updates: `GET /api/v1/hr/data-updates`, `GET /api/v1/hr/data-updates/{id}`,
     `POST /api/v1/hr/data-updates/{id}:approve`, `POST …:reject` (ActionRequest, `reason` required on reject;
     permissions `hr.data_update.read` (new code proposed) for reads — today `hr.data_update.read` falls under the
     `hr.*.*` grant of the HR role; actions use `hr.employee.update`). Schema `DataUpdate {id, tenant_id, company_id,
     status, employee_id (restricted-pii), changes (restricted-pii), review_status, version, audit}`.
  3. Additional properties (all registered in `hr/fields.py` with these classifications):
     * `EmploymentContract`: `salary_type` (ORDINARIO|INTEGRAL), `arl_risk_class` (I–V), `cost_center_id`, `position_id`,
       `exonerated` — internal (payroll inputs of `PayrollEmployee`).
     * `EmployeeInput/Patch`: write-only `data_consent` (restricted-pii; Ley 1581 authorisation, `consent_required`
       when missing) and `biometric_consent` (sensitive-pii; R-DP-01).
     * `Absence.days` (Decimal string, read-only), `ClockEvent.method` (WEB|KIOSK_PIN|KIOSK_QR|MOBILE|BIOMETRIC),
       `Timesheet.hours` / `warnings` / `parameters` (read-only, classification result + parameter snapshots).
     * `:clock-in` / `:clock-out` ActionRequest `parameters`: `{employee_id, method, device, geo, biometric_match}`.
* Not routed (documented in the contract, no implementation in this part): `/api/v1/hr/self-service/*` — internal
  users would need a user ↔ employee link; employees use the employee portal. Proposal: link `iam.User` to
  `hr.Employee` in a later CCR or drop the internal self-service paths in favour of the portal.

# CCR P01-5 — notes for IAM (P04) and ledger (P05)

* From: P01 · To: P04, P05 · Type: integration notes · Status: OPEN (no kernel change required)
* P04:
  * Set `request.erp_context` (a `kernel.tenancy.TenantContext`) in the authentication layer, or point
    `ERP_TENANT_CONTEXT_RESOLVER` at a resolver; DRF views must activate it (`with tenancy.activate(ctx)`) because DRF
    authenticates after middleware. Add authentication classes to `REST_FRAMEWORK` via CCR to P01 (settings owner).
  * RLS: kernel tenant tables `kernel_idempotency`, `kernel_sequence` (company-scoped) and `kernel_feature_flag` should get
    policies (reference SQL: `kernel.db.rls_policy_sql`). `kernel_outbox`, `kernel_inbox`, `kernel_dead_letter` are
    platform tables read by the relay/worker role; decide the role grants (ADR-003 `erp_platform`) and tell P01 if the
    relay must bind a context.
  * Company table must expose `UNIQUE (tenant_id, id)` so `kernel.db.company_fk_sql()` composite FKs can reference it.
  * Register a `PolicyService` implementation with `kernel.services.register` at app ready.
* P05:
  * `kernel.dimensions` registers FK targets `ledger.CostCenter`, `ledger.BusinessUnit`, `ledger.AuxAbierto`,
    `ledger.ItemContable` (names chosen by P01); if your model names differ, file a CCR and P01 updates the registry.
  * Implement `kernel.interfaces.PeriodService` (feeds `/api/v1/ui/context` `period`) and `PostingService`.

# CCR P11b-4 — portal hooks of `purchasing.interfaces` deny real portal principals (P11a)

* From: P11b · To: P11a · Type: bug (interface) · Status: OPEN
* Problem: `portal_submit_quote` authorizes `portal.supplier_quote.create` with the **RFQ** as resource
  (`services.rfq.create_quote` → `require(ctx, permission, rfq)`) and `portal_acknowledge_order` authorizes
  `portal.supplier_purchase_order.update` with `{"supplier_id": …}`. P04's engine decides portal ownership on
  `company_id` + `party_id` of the resource (`PolicyEngine._authorize_portal` → `portal_owns`): neither resource carries a
  party, so every real supplier token is denied (`external_account_scope_violation`). P11a's own test uses a grant-only
  policy double, so it did not show up.
* Request: pass `{"company_id": rfq.company_id, "party_id": supplier.party_id}` (resp. the order's company and its
  supplier's party) as the resource, after checking the invitation / ownership as today.
* Meanwhile (P11b, `backend/purchasing/portal/bridge.py`): around exactly these two calls, a delegating `PolicyService`
  translates those two resources into the `{company_id, party_id}` the engine expects (owned only when the portal
  principal's supplier is invited / is the order's supplier); the real engine still decides; other calls are unchanged.
  Remove the bridge when this CCR is applied (tests `test_portal_sup_quotes_orders.py` keep covering it).

# CCR P13a-1 — publish the HR interfaces in `kernel.interfaces.hr`

* From: P13a (HR provider) · To: integrator (owner of `backend/kernel/**`), P13b (payroll) · Type: additive interface · Status: OPEN
* Answers CCR P13b-1.
* Today (`backend/kernel/**` is not a P13a path) the interfaces live in `backend/hr/interfaces.py`:
  * `PayrollEmployee` / `PayrollEmployeeSource` — **exactly** the shape frozen by P13b in `payroll.interfaces`
    (same fields, same defaults, same method signature).
  * `EmployeePayslipView` / `EmployeePayslipSource` — POSTED payslips of one employee for the employee portal
    (`payslips_of(tenant_id, company_id, employee_id)`, `payslip(tenant_id, company_id, payslip_id)`).
* Wiring already in place (`backend/hr/wiring.py`, at app ready, never replacing an earlier registration):
  * `hr.directory.DbPayrollEmployeeSource` is registered against `hr.interfaces.PayrollEmployeeSource` **and**, when the
    payroll app is installed, against `payroll.interfaces.PayrollEmployeeSource` (instances of payroll's own dataclass).
  * `hr.portal.payslips.PayrollTablesPayslipSource` (read-only adapter over `payroll.Payslip` / `PayrollRun` /
    `PayrollPeriod`, POSTED only, resolved via `apps.get_model`) is registered against `EmployeePayslipSource` when the
    payroll app is installed.
* Requested:
  1. Move both pairs to `backend/kernel/interfaces/hr.py` unchanged and export them from `kernel.interfaces`
     (`FEATURE_STUBS` if wanted); `hr.interfaces` and `payroll.interfaces` then re-export (one import line each).
  2. After the move, the double registration in `hr/wiring.py` collapses to one (P13a or the integrator).

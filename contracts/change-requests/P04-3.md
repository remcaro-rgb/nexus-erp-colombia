# CCR P04-3 — `kernel.interfaces.Dimensions.list_nodes` + hierarchy version (P01 interface, P05 implementation)

* From: P04 · To: P01 (`kernel.interfaces`) and P05 (ledger dimensions) · Type: additive · Status: OPEN
* Why: role scopes by cost-center subtree (T-ACC-DIM-09) are expanded with `Dimensions.subtree()`. The scope projection
  `GET /api/v1/iam/cost-centers` (list/tree/search) also needs to enumerate a company's nodes, which the frozen protocol
  cannot do. `iam.dimensions.all_nodes()` calls `list_nodes(company_id, dimension) -> list[DimensionNode]` when the provider
  has it and returns an empty list otherwise (fail closed). Test double: `iam.testing.fakes.ListableDimensions`.
* Requests:
  1. Add `list_nodes(company_id, dimension, valid_on=None) -> list[DimensionNode]` to the protocol and implement it in P05.
  2. Optional: `hierarchy_version(company_id, dimension) -> int` bumped on move/re-parent; IAM would add it to the policy
     cache key. Today expanded subtrees are cached ≤ 300 s (assignment/role changes invalidate immediately via
     `policy_version`; only a re-parent in P05 can be seen up to 5 minutes late).
  3. P05 should apply `iam.policy.scope_queryset` on its dimension list/tree/export endpoints (the subtree grant is the
     role-assignment scope key `cost_center_ids`).

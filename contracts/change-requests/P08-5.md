# CCR P08-5 — migrate the frontend from zod 3 to zod 4 (OPEN, owner P08, follow-up)

Raised by: P08 attempt 3 · Owner: P08 (root `package.json` / `pnpm-lock.yaml`, `frontend/src/lib/**`) ·
Consumers: every `frontend/src/features/**` (all form/schema code), `@hookform/resolvers`.

## Problem
`pnpm audit` reports one **high** advisory on the pinned `zod 3.25.76` (`.>zod`):
GHSA-mrhx-c7xc-m3w5 — memory exhaustion on oversized constrained collections; patched in `>=4.6.6`.
The CI policy gate (`scripts/ci/ci-parity.sh`, `pnpm audit --audit-level critical`) does not fail on *high*, so this
does not block wave 02, but it must not stay open indefinitely.

## Why not in attempt 3
zod 4 is a major release (changed error API/`issues` shape, `z.string().email()` → `z.email()`, `.strict()`/`.passthrough()`
semantics, `ZodError.format/flatten`, `errorMap` → `error`), affecting `@hookform/resolvers` and every feature's schemas
owned by other tasks. Doing it in a last-attempt dependency fix would be an untested cross-task change.

## Requested change (scheduled follow-up)
1. P08 pins `zod` to the latest 4.x ≥ 4.6.6 (released ≥ 2 weeks before use, D-028) and a compatible `@hookform/resolvers`;
   migrates `frontend/src/lib/**` and design-system form helpers.
2. Each feature owner migrates its `frontend/src/features/**` schemas in the same wave (codemod list attached by P08).
3. Acceptance: `pnpm audit --audit-level high` exits 0; `tsc --noEmit`, vitest and Playwright suites green.

## Mitigation meanwhile
The backend re-validates every payload (client schemas are input help only) and client schemas only parse user-sized form input.

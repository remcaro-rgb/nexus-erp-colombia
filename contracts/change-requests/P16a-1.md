# CCR P16a-1 — AP open-item application interface and additive treasury contract fields

* From: P16a · To: P11 (purchasing / AP), P02 (contracts) · Type: interface + additive schema · Status: OPEN
* **AP application interface.** P11a exposes no way to apply a payment to `purchasing_ap_open_item`. P16a defines
  `treasury.interfaces.ApOpenItems` (`open_items`, `get`, `apply`, `unapply`; same rules as `kernel.interfaces.ArOpenItems`:
  caller's UoW, row locks in ascending id, never over-applies → `treasury_overapplication`, COP at the item's historical
  rate) and implements it over P11's table in `treasury/vouchers/ap.py` (`PurchasingApOpenItems`), recording each
  application in `treasury_ap_application`. Request: P11 adopts the protocol (ideally as `kernel.interfaces.ApOpenItems`
  with an `ApApplication` table in purchasing) and registers its implementation; treasury then drops its adapter (the
  registry lookup `services.get(ApOpenItems)` stays the same).
* **`PaymentBatchLine` (treasury.yaml)** has no payee or open item. P16a accepts, additively, `party` (PartyRef),
  `open_item_id` (uuid, nullable = vendor advance) and `applied_amount` (Money) on input; responses keep the frozen schema
  (payee + document number travel in `description`). Request: add the three properties to `PaymentBatchLine`.
* **`TreasuryConcept`**: the FEATURES-ADDENDUM model has `requires_party`, `default dims`, `approval_threshold` and a
  withholding profile; the frozen schema has none of them. P16a stores them (service/seed only, `create_concept(...,
  extended=True)`). Request: add `requires_party` (bool), `default_dimensions` (DimensionSlots), `approval_threshold`
  (Money, nullable) and `withholding_codes` (string[]) to `TreasuryConcept*`.
* **Voucher lines**: the line `kind` of the addendum is derived (open item → application, concept → concept, tax code
  alone → withholding with `unit_price` = base, otherwise advance). Request (optional): an explicit read-only `kind` in
  `CashReceiptLine` / `DisbursementLine` responses.
* **`:execute` / `:generate-file`** answer the contract `Operation` plus a `file` object (`label` FIXTURE_NOT_CERTIFIED,
  `name`, `sha256`, `content`). Request: document `file` in the response or add a `GET …/payment-batches/{id}/file`.

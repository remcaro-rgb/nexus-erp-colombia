# CCR P07-1 — install the workflow app, mount its routes, schedule its beat tasks

* From: P07 · To: P01 (settings/urls owner) / integrator · Type: additive wiring · Status: OPEN
* Why: `backend/erp/settings/base.py` and `backend/erp/urls.py` are not P07 paths. Until this CCR is applied,
  `backend/workflow/tests/conftest.py` installs the app at collection time (before the test DB is created) so the
  workflow migrations and DB tests run in `make ci`; the shim is a no-op once the app is in `INSTALLED_APPS`.
* Requested changes:
  1. `INSTALLED_APPS += ["workflow"]` (after `"kernel"`). `WorkflowConfig.ready()` registers `AuditService`,
     `WorkflowService`, `SchedulerService`, `NotificationService` and `FileStore` with `kernel.services` (only when no
     implementation is registered yet).
  2. `backend/erp/urls.py`:
     ```python
     from workflow.urls import kpi_urlpatterns
     path("api/v1/workflow/", include("workflow.urls")),
     path("api/v1/kpis/", include((kpi_urlpatterns, "kpis"))),   # GET /api/v1/kpis/aprobaciones
     ```
  3. Optional setting `ERP_FILESTORE_ROOT` (DEV local object store root; default `<repo>/.filestore`, which should be
     gitignored — `.gitignore` is protected, integrator please add `.filestore/`).
  4. Celery beat (DEV stack): `workflow.scheduler_tick` every 60 s and `workflow.deliver_webhooks` every 60 s; the
     tick is single-leader by a PostgreSQL advisory lock, so several beat/worker replicas are safe.
  5. `pyproject.toml`: add `backend/workflow` to `[tool.coverage.run] source` and, if desired, `mypy backend/workflow`
     to `make typecheck`.
* After (1)–(2), `python manage.py makemigrations --check` must stay clean: migrations `workflow/0001_initial` and
  `0002_append_only` were generated with Django 5.2.19 from the current models.

# CCR P04-4 — RLS on kernel tenant tables and wiring notes for P09/P12 (branches)

* From: P04 · To: P01 (kernel migrations), P09, P12 · Type: integration · Status: OPEN
1. P01-5 asked P04 to add RLS to `kernel_idempotency`, `kernel_sequence`, `kernel_feature_flag`. These tables are created
   by kernel migrations (P01 paths); a policy added from an `iam` migration would make the kernel's own unit tests (which
   query them without a bound context) depend on IAM. Request: P01 adds `iam.rls.enable("kernel_sequence")` (company
   scoped) and `iam.rls.enable("kernel_idempotency", company_scoped=False)` / `kernel_feature_flag` in a kernel migration
   that depends on `("iam", "0002_security")`, or tells P04 to do it. `iam.rls.tables_without_rls()` lists any table with
   `tenant_id` lacking forced RLS (the P04 test checks the `iam_` prefix; widen it once kernel tables are covered).
2. P09 (`Warehouse.branch_id`) and P12 (`PosConfig.branch_id`): add the composite FK with
   `iam.branches.db.branch_fk("<table>")` in your migration (depends on `("iam", "0002_security")`), call
   `iam.branches.services.validate_branch_link(ctx, company_id, branch_id)` in your create/update services, and register
   `BranchReference("inventory.warehouse" | "pos.config", table, active_sql="status = 'ACTIVE'")` at app ready so
   `:archive` reports `branch_in_use` with the dependency list and `default_warehouse_id` is validated.

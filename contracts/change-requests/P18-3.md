# P18-3 — dataio contract details: JSON file transport, job options, shell export body (to P02 / P08)

Status: OPEN (P18, wave 06). Additive; no existing operation changes behaviour.

1. **P08 `ApiClient` is JSON-only** (`frontend/src/lib/api/client.ts`): it cannot send `multipart/form-data` nor read
   binary responses. Implemented additively in dataio:
   * `POST /api/v1/dataio/imports/{id}:upload` also accepts JSON `{filename, content_base64}` (multipart `file` stays the
     contract form);
   * `GET …/templates/{entity}/download`, `GET …/exports/{id}/file`, `GET …/imports/{id}/report` accept
     `?encoding=base64` and then answer JSON `{filename, content_type, content_base64}`.
   Request to P08: optional `api.upload(path, FormData)` and `api.download(path)` (Blob) in the shell client; the
   frontend feature then drops the base64 variant.
2. **File format query parameter is `file_format`**, not `format`: DRF reserves `?format=` for renderer negotiation
   (it answers 404 for `csv`/`xlsx`). Request to P02: document `file_format` (csv|xlsx|jsonl|json) on those GETs.
3. **`ImportJobInput`** (contract: `entity` only, `additionalProperties: false`) also takes `mode`
   (`create_only|update_only|upsert`, default `upsert`), `batch_size` (0 = one all-or-nothing batch) and
   `decimal_comma` (es-CO `1.234,5`). Request to P02: add them to the schema.
4. **`ExportJobInput`** (`source`, `format`) also accepts the body the P08 module bar already sends
   (`entity`, `params`, `company_id`, `period_id`; `entity` ≡ `source`, `format` defaults to `csv`, `company_id` must equal
   the request company). Request to P02: add these optional properties.
5. `/api/v1/dataio/templates/{id}` is served by entity slug (`/templates/dimensions`), not by UUID: templates are code
   (no table). Request to P02: change the path parameter to `{entity}` (string).

# CCR P07-2 — IAM integration points for workflow (P04)

* From: P07 · To: P04 · Type: integration · Status: OPEN
1. **Approver directory.** Approvals resolve `role` and `manager` approvers through the protocol
   `workflow.approvals.directory.ApproverDirectory` (`members_of_role(ctx, company_id, role)`,
   `manager_of(ctx, company_id, principal_id)`), looked up in `kernel.services`. Please register an implementation
   backed by IAM roles (and HR's org chart, P13, for `manager_of`). Until then a deny-by-default empty
   `StaticDirectory` is used (no role has members, nobody has a manager → `approver_unresolved`).
2. **SoD.** Every decision calls `PolicyService.authorize(ctx, "workflow.approval.approve", request)`. When P04 denies
   because of a segregation-of-duties rule, put `sod` in `Decision.reason` so the API returns `sod_violation`
   (otherwise `permission_denied`). The requester-never-approves rule (D-023) is enforced by P07 itself.
3. **Field masks used** (`PolicyService.field_mask`): `workflow.approval` → `amount`; `workflow.audit_event` → `ip`,
   `user_agent`; `<audited resource_type>` → which changed fields an audit reader may see in clear (others show
   `{"changed": true}`); `<event resource>` (e.g. `ledger.journal_entry.posted`) for webhook payload filtering of the
   subscriber's service account, plus `<module>.event.read` to receive the event at all.
4. **Module permissions in the UI registry.** `module-registry.json` uses `workflow.read`, `audit.read` and
   `scheduler.read` for the module/submenus; the API uses the catalog codes `workflow.approval.read`,
   `workflow.audit_event.read` and `workflow.scheduled_job.read`. Please map the registry codes to those catalog
   codes in the nav filter (P04/P08) — P07 does not add two-part codes to the catalog.
5. **RLS** (reference SQL `kernel.db.rls_policy_sql`): company-scoped tables `workflow_formula`,
   `workflow_formula_table`, `workflow_formula_evaluation`, `workflow_approval_policy`, `workflow_approval_request`,
   `workflow_approval_delegation`, `workflow_scheduled_job`, `workflow_notification`, `workflow_attachment`,
   `workflow_webhook_subscription`, `workflow_dsr_request`; tenant-only tables `workflow_audit_event` (company_id is
   nullable), `workflow_audit_anchor`, `workflow_approval_assignment`, `workflow_approval_decision`,
   `workflow_job_run`, `workflow_notification_preference`, `workflow_webhook_delivery`. The scheduler leader and the
   webhook deliverer read across tenants and need the platform role (ADR-003 `erp_platform`), like the outbox relay.
6. **Delegated grants for AI-created jobs.** `ScheduledJob.grant_ref` stores the delegated grant id; at every run
   the scheduler calls `authorize(owner_ctx, <job type permission>, {"grant_ref": ..., "job": ...})` with an
   `AI_AGENT` context `on_behalf_of` the owner. Please validate the grant there (revoked grant → deny → job FAILED).

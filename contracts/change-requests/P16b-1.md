# CCR P16b-1 — consolidation contract: additive fields for members, mapping, reversal and IC actions

* From: P16b · To: P02 / integrator (`contracts/src/modules/consolidation.yaml`, `intercompany.yaml`, regenerate) · Type: additive · Status: OPEN

`consolidation.yaml` / `intercompany.yaml` 1.0.0 are consumed **unchanged** (generated files; P16b owns the
generated module file but not its source). The P16 [A] scope needs these additive items; the service layer
(`backend/consolidation/service.py`, `intercompany.py`) already implements them, the API exposes only the frozen shapes.

1. **ConsolidationGroup**: `members[]` `{company_id, ownership_pct (Percent), method FULL|PROPORTIONAL|EQUITY,
   equity_historical_rate (Rate, COP per presentation unit), investment_account_code}` (today: `service.configure_member`;
   default 100 % FULL), `account_maps[]` `{company_id|null, local_prefix, group_account, group_name}`
   (`service.set_account_map`; default identity), `closed_through` (YYYY-MM, `service.close_period`), `settings`
   (generated group accounts: `cta, nci, nci_profit, goodwill, bargain_gain, ic_difference, equity_method_income,
   equity_method_investment`).
2. **ConsolidationRun**: action `:reverse` (permission `consolidation.run.void`, `reason` required) — today
   `service.reverse_run`; read-only `summary` (per-company contributions, CTA, IC differences, rates snapshot).
3. **IntercompanyAgreement**: the free-form `accounts` object already carries the role overrides
   (`ic_receivable, ic_payable, revenue, cogs, inventory, vat_payable, vat_recoverable, expense, bank`) and
   `pricing_rule, markup_pct, auto_mirror, default_warehouse_id`; request: promote the last four to typed fields.
4. **Intercompany documents/links** (read API): `GET /api/v1/intercompany/links` (`ic_link_id`, A/B documents and
   entries) and `GET /api/v1/intercompany/documents` (B-side mirror invoices, company scoped), plus action
   `POST /api/v1/intercompany/settlements` (`intercompany.document.post`) for IC payments/netting from the UI.
5. Event `intercompany.mismatch.detected.v1` is emitted when a consolidation run is posted with IC differences
   (company_id = the agreement's company A). No schema change.

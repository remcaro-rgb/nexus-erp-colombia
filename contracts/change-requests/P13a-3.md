# CCR P13a-3 — synthetic HR / time keeping parameters and a shared field-encryption helper

* From: P13a · To: P06 (parameter store / seed), integrator (kernel) · Type: data + helper · Status: OPEN
* HR and time keeping read these legal parameters through `kernel.parameters` (UNKNOWN fails closed). They are **not**
  in the P06 seed yet, so in the DEV stack the vacation KPI shows `not_available`, integral contracts and timesheet
  submission answer `parameter_unknown`. Please add labelled synthetic fixture rows (`synthetic: true`,
  NOT LEGALLY VERIFIED, status from the source review; never official figures without legal review EG-7):
  * `hr.vacaciones.dias_habiles_anio` (decimal; days of vacation per year of service)
  * `hr.salario_integral.min_smmlv` (decimal; integral salary minimum expressed in SMMLV)
  * `hr.jornada.nocturna_inicio`, `hr.jornada.nocturna_fin` (time `HH:MM`; two rows around the 2025-12-25 change)
  * `hr.jornada.horas_diarias_ordinarias`, `hr.jornada.horas_extra_max_dia` (decimal)
  * `smmlv`, `uvt` are already referenced by payroll (P13b) — certificates show their status only.
  The values used by the tests are in `backend/hr/testing/fakes.py::legal_parameters` (synthetic).
* Field encryption: the bank account is encrypted with a stdlib HMAC-SHA256 CTR + encrypt-then-MAC construction in
  `backend/hr/crypto.py` (key = `settings.ERP_FIELD_ENCRYPTION_KEY`), because no AEAD library is in `uv.lock` and
  `pyproject.toml` is not a P13a path. Proposal: a kernel `EncryptedTextField` (e.g. AES-GCM via `cryptography`)
  shared by every module; P13a would migrate `hr_employee.bank_account_enc` to it.

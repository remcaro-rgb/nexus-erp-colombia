# CCR P08-3 — config-less `playwright test` in `make test-ids` / `make e2e` loads Vitest files (OPEN, to integrator / P01)

Raised by: P08 attempt 2 · Target: P01 `Makefile` or the integrator (`frontend/playwright.config.ts` is not an owned path).

## Problem
`make test-ids` runs `pnpm --dir frontend exec playwright test --grep …` without `--config`. Playwright then uses its
default `testMatch` (`**/*.@(spec|test).?(c|m)[jt]s?(x)`) over all of `frontend/`. Since wave 02, P04/P07 ship Vitest
unit tests named `*.test.ts` (`frontend/src/features/tax/__tests__/model.test.ts`,
`frontend/src/features/workflow/__tests__/module.test.ts`). Playwright loads them, they import `vitest`
("Vitest failed to access its internal state") and a JSON module without an import attribute, and the Playwright
half of `make test-ids` exits 1 even though no Playwright test is selected. The Vitest half (JUnit) is unaffected.

## Requested change (either one)
1. Add `frontend/playwright.config.ts` (one line, integrator):
   `export { default } from "./src/app/e2e/playwright.config";`  — that config only matches `*.e2e.ts`, uses
   `$CHROME_PATH` and writes `reports/playwright/results.json` (honours `PLAYWRIGHT_JSON_OUTPUT_NAME`); or
2. P01 Makefile: pass `--config src/app/e2e/playwright.config.ts` (or P22's config once it exists) to both
   `playwright test` calls.

## Meanwhile (P08 attempt 2)
* Vitest now also includes `src/**/__tests__/**/*.test.{ts,tsx}`, so P04/P07 frontend tests run in `make ci`.
* P08's mandatory tests are Vitest tests and are collected from `reports/junit/test-ids-frontend.xml`.
* Feature tasks: name Vitest files `*.unit.ts(x)` (P08 convention, see `frontend/src/design-system/UX-GUIDE.md`)
  and Playwright specs `*.e2e.ts` until this CCR lands.

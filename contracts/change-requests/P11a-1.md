# CCR P11a-1 — purchasing contract: additive fields the F-PUR-CYCLE implementation needs

* From: P11a · To: P02 / integrator (`contracts/src/modules/purchasing.yaml`, regenerate) · Type: additive contract change · Status: OPEN

The generated schemas of `contracts/openapi/modules/purchasing.yaml` use the generic document line
(`line_no, item_id, description, quantity, unit_price, amount, tax_code, account_code, dimensions`) and the
generic document status enum. F-PUR-CYCLE (FEATURES-ADDENDUM §14) needs these **additive** properties; the API
already accepts/returns them (P11a, `backend/purchasing/api/serializers.py`). Paths, methods, permissions and
error codes are unchanged.

1. **Rfq**: `status` enum per §14 (`DRAFT, SENT, CLOSED, EVALUATED, AWARD_PENDING_APPROVAL, AWARDED, PO_CREATED, CANCELLED`);
   read-only `award` (`{id, status, recommended_quote_id, differs_from_recommendation, reason, proposed_by,
   approval_request_id, decided_by, lines[{rfq_line_id, quote_id}]}`), `reopen_count`, `reopen_reason`, `terms`,
   `warnings[]` (`fewer_than_3_vendors`, D-010). Lines: read-only `id`, `source_line_id` (requisition lineage, P11b).
2. **VendorQuote**: `rfq_id` (ro), `fx_rate` (Rate; required for non-COP quotes unless a ledger rate exists on the quote
   date → `quote_currency_rate_missing`), `freight_amount` (header freight, allocated by net value), `valid_until`,
   `channel` (`internal_entry|supplier_portal`, ro), `warnings[]` (`quote_late`, D-010), `quote_status` adds `WITHDRAWN`
   (DELETE withdraws, never deletes). Lines: `rfq_line_id`, `factor_to_base` (UnitCost, presentation → base UoM, D-013),
   `presentation_id`, `discount_pct`, `tax_rate_pct` (else from TaxService for `tax_code`), `tax_recoverable` (bool),
   `freight_amount`, `lead_time_days`, `notes`.
3. **Action parameters** (`ActionRequest.parameters`): `:award` → `quote_id` or `lines[{rfq_line_id, quote_id}]`
   (+ `reason`, required when the award differs from the recommendation); `:approve-award` → `approve` (bool, default
   true; rejection needs `reason`); `:reopen` → `deadline` (date-time, future; `reason` required).
   `orders:{id}:approve` → `approve` (bool, default true).
4. **Comparison report** (`GET /rfqs/{id}/comparison`): `{id, rfq_id, sequence, created_at, created_by, weights,
   ranked[], excluded[], recommended_quote_id, tie_rule, explanation, warnings}`; each quote row
   `{quote_id, vendor_id, vendor_code, vendor_name, received_at, currency, fx_rate, lead_time_days, payment_terms_days,
   rating, comparable_total_cop, lines[], rank, factors, points, score}` (excluded rows carry `reason`
   `LATE|WITHDRAWN|DISQUALIFIED|INCOMPLETE`). Classification: `comparable_total_cop` and line prices confidential.
5. **PurchaseOrder**: `status` enum `DRAFT, SUBMITTED, APPROVED, REJECTED, SENT, ACKNOWLEDGED, PARTIALLY_RECEIVED, RECEIVED,
   CLOSED, CANCELLED`; `fx_rate`; lines `id`, `warehouse_id`, ro `received_qty`, `invoiced_qty`.
6. **PurchaseReceipt**: lines `order_line_id` (input); ro `receipt_status` (`DRAFT|VALIDATED|CANCELLED`; `status` maps
   VALIDATED → POSTED), `journal_entry_id`.
7. **VendorInvoice**: input `order` (DocumentRef), `fx_rate`; lines `order_line_id`, `account_role` (non-PO lines,
   default EXPENSE), `withholding_codes[]`, `withholding_concept`; ro `match_status` (`UNMATCHED|MATCHED|MISMATCH`),
   `match_result` (per-line issues `quantity|quantity_not_received|price|currency|no_purchase_order`), `subtotal`,
   `tax_total`, `withholding_total`, `journal_entry_id`.
8. **ApOpenItem**: `document_date`, `amount` (Money), `balance_cop` (Money, confidential).

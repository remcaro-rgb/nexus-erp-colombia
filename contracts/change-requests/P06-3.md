# CCR P06-3 — additions to the tax contract (`contracts/src/modules/tax.yaml`)

* From: P06 · To: P02 (contracts) · Status: OPEN · Compatibility: additive (minor version)

The implementation follows the frozen contract and needs these additive changes so that clients can use the
two-person workflow and the engine without undocumented fields:

1. `Parameter` (response): add read-only `approval` (PROPOSED | APPROVED | REJECTED | SUPERSEDED), `proposed_by` (uuid),
   `scope` (global | company | municipality), `scope_ref`, `legal_history` (array of {event, date, source, note}),
   `supersedes_id` (uuid|null), `notes`. The implementation already returns them; `value` is `{type, value|rows|data}`.
2. `POST /parameters:propose` and `/parameters/{id}:propose`: document `ActionRequest.parameters` as
   `{code, value_type (decimal|percent|permil|uvt|table|json|unknown), value, valid_from, valid_to, parameter_status,
   source_id | source{url,title,accessed_at,method,excerpt_hash}, company_id, scope_ref, document_ref, synthetic, notes,
   legal_history}`; `:approve` takes `parameters.legal_review: boolean` (sets the EG-7 stamp). Error `sod_violation`
   when the proposer approves.
3. New `GET /api/v1/tax/parameters/{id}/impact` (permission `tax.parameter.read`) →
   `{parameter_id, code, valid_from, valid_to, providers[], affected[{provider, document_type, document_id, number, reason}], count}`.
4. `PartyTaxProfile` / input: add `person_type`, `gran_contribuyente`, `autorretenedor`, `vat_withholding_agent`,
   `ica_municipalities[]`, `ciiu_codes[]` (the engine needs them for the applicability matrix).
5. `TaxCode` / input: add `tax_type` value `AUTORRETENCION` (prompt list), `base_rule` (NET | TAX_AMOUNT | PERCENT_OF_BASE),
   `base_tax_type`, `min_base_uvt_parameter_code`, `applicability[]` (matrix rules, see `tax/engine/matrix.py`).
6. `POST /compute`: document `parameters` = `{document_type, document_date, party_id, municipality,
   rounding_mode (LINE|DOCUMENT), seller?, buyer?, lines[{line_ref, base_amount (decimal string), tax_codes[], concept,
   activity_code}]}` and `ActionResult.data` = engine result (lines, totals, tax_total, withholding_total,
   rounding_adjustment, parameter_snapshots, warnings, trace).
7. Holiday overrides (admin): `POST/DELETE /api/v1/tax/localization/holiday-overrides` (permission `tax.holiday.update`,
   new code) — model `localization_co.HolidayOverride` exists; endpoint not exposed until the contract has it.
8. The module registry uses permission `tax.read` for the Impuestos submenu, which does not follow the catalog grammar
   `<module>.<resource>.<action>`; either add `tax.read` as an alias in the catalog or change the registry to
   `tax.parameter.read`. P06's UI descriptor uses the registry value.

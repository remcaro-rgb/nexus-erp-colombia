# CCR P16a-2 — ArOpenItems: COP amounts, foreign currency and the permission used by treasury

* From: P16a · To: P10 (sales / AR), P01 (kernel.interfaces) · Type: interface (minor, additive) · Status: OPEN
* `ArOpenItems.apply` returns `None` and `OpenItem` carries no historical rate, so treasury cannot credit AR at the
  item's historical COP when the receipt is in a foreign currency (realized FX difference). P16a therefore applies open
  items only in COP vouchers of the item currency (`treasury_currency_mismatch` otherwise). Request: `apply` returns
  `list[(open_item_id, amount, amount_cop)]` (as `sales.services.ar.apply_amounts` already computes) and `OpenItem` gains
  `fx_rate`; P16a then posts FX_REALIZED_GAIN/LOSS like `sales.services.collections.post_receipt`.
* `SalesArOpenItems.apply/unapply` require `sales.receipt.post`. Treasury roles therefore also need that code. Request:
  accept `treasury.receipt.post` (or a dedicated `sales.ar_application.post`) so a cashier needs no sales permission.
* `sales.receipt.posted.v1` / P10's own receipt API stay as they are; per the FEATURES-ADDENDUM "Supersedes", P10's
  `/receipts` should become the AR-application view of the RC voucher (P10 may call `treasury.vouchers.service`).

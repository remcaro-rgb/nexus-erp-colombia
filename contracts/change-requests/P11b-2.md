# CCR P11b-2 — additive contract fields and routes for F-INV-REQ / F-PORTAL-SUP (P02 contract, P11)

* From: P11b · To: P02 (contracts) / P11a (purchasing.yaml owner) / P08+P04 (portal.yaml) · Type: contract (additive) · Status: OPEN
* Read-only response fields served today (additive; the frozen schemas set `additionalProperties: false`):
  * `InternalRequisition`: `requisition_status` (full F-INV-REQ state: IN_PROGRESS, FULFILLED,
    PARTIALLY_FULFILLED_CLOSED; `status` keeps the contract enum: IN_PROGRESS→APPROVED, FULFILLED/closed→POSTED),
    `requester_id`, `decided_by`; lines: `id`, `base_qty`, `line_status`, `qty_transfer`, `qty_procure`,
    `qty_cancelled`, `fulfilled_qty`, `delivery_warehouse_id`, `needed_by`, `lineage[]`. `:approve` also returns
    `sourcing` (the D-012 result of the automatic sourcing).
  * `consolidations:run` returns the `Operation` (run synchronously, `SUCCEEDED`) plus `dry_run`, `lines[]` (D-031 groups
    with `sources[]` lineage, D-011 `action` DRAFT_PO|BUYER_TASK, `reason_code`, `estimated_total`) and `warnings[]`
    (`auto_po_limit_exceeded`). `Consolidation` adds `number`, `rule`; `lines` carries `buyer_tasks[]`.
  * `PurchaseRequisition.target` (DocumentRef of the RFQ/PO created by `:to-rfq` / `:to-po`).
  * Portal: `SupplierRfq.currency`, `SupplierRfq.lines[]` (what to quote); `SupplierQuoteSubmission.number`, lines with
    the supplier's own `unit_price`/`discount_pct`; `SupplierPurchaseOrder.document_date`, `expected_date`, `lines[]`
    (own agreed prices, received qty), `answer` (accepted / changes requested; status `CHANGE_REQUESTED`);
    `SupplierShipment.number`, `tracking`; `SupplierPayment.vouchers[]`.
* Routes not yet in the contract (served / needed):
  * `GET /api/portal/v1/supplier/kpis?period=YYYY-MM` — dashboard KPIs (same pattern as CCR P13a-2). The P08 shell calls
    a generic `/api/portal/v1/kpis?portal=supplier`; P08/P04 may route it to this provider.
  * Internal (service functions exist, no route yet): profile-change inbox and decision
    (`purchasing.portal.service.pending_profile_changes` / `decide_profile_change`, permissions
    `purchasing.supplier_profile_change.{read,approve}`), shipment notices for receiving
    (`notices_for_receiving`, `purchasing.shipment_notice.read`), buyer tasks list. Suggested:
    `GET/POST /api/v1/purchasing/supplier-profile-changes[/{id}:approve|:reject]`,
    `GET /api/v1/purchasing/shipment-notices?order_id=`, `GET /api/v1/purchasing/buyer-tasks`.
* Not served: `POST internal-requisitions:import` (CSV as DRAFT) — no fake endpoint was added.

# CCR P14-7 — fixed-assets contract amendments (P02, contracts/src/modules/assets.yaml)

* From: P14 · To: P02 / integrator · Type: contract · Status: OPEN
* The frozen `assets.yaml` 1.0.0 is implemented as is (no extra endpoints, `additionalProperties: false` honoured).
  The P14 domain needs these additive changes (minor version):
  1. `FixedAsset`: `lifecycle_status` ∈ {DRAFT, ACTIVE, FULLY_DEPRECIATED, DISPOSED} (today mapped to `status`
     ACTIVE/ARCHIVED), `in_service_date`, `parent_id` (component of), `serial`, `books[]` (book_id, method,
     useful_life_months, salvage_value, cost, accumulated_depreciation, accumulated_impairment, net_book_value).
  2. `POST /api/v1/assets/assets/{id}:change-estimate` (`assets.asset.update`, reason required; parameters book_id,
     useful_life_months, salvage_value, method, units_total) — implemented as `assets.service.change_estimate`
     (prospective, audited) but not routed until it is in the contract.
  3. `AssetCategory`: per-book defaults (`books[]`: book_id, method, useful_life_months, salvage_pct,
     rate_parameter_code), `min/max_life_months`, `capitalization_threshold`, `capitalization_threshold_uvt`; method
     enum + `SUM_OF_YEARS` ([A]).
  4. `PhysicalCount`: `discrepancies` {found, missing, unknown, duplicates} (today represented by the lines: missing
     assets as quantity 0, unknown tags without `item_id`).
  5. `:dispose` / `:activate` / `:transfer` `parameters` schemas (documented in `docs/handoffs/P14.md`).

# CCR P14-1 — book-specific posting in the PostingService (P05)

* From: P14 · To: P05 (owner of `backend/ledger/**`, `kernel.interfaces.posting` consumer contract) · Type: interface · Status: OPEN
* Need: shared/07 §5 requires **separate entries per book** for depreciation (NIIF vs fiscal), and the amounts of
  revaluation, impairment, transfers (reclass) and disposals also differ per book. The frozen `PostingService.post`
  writes one entry into **every** mirror book with the same amounts.
* Request: add to the ledger implementation (and, via P01, to `kernel/interfaces/posting.py`)
  `post_to_book(uow, request, book_code) -> PostingResult` and `simulate_to_book(uow, request, book_code) -> list[line]`
  (or an optional `PostingRequest.books: tuple[str, ...] | None`), with the same checks, numbering, balances,
  outbox event and idempotency key `(company, source.type, source.id, purpose)`.
* Meanwhile (P14, `backend/assets/posting.py`): when the registered service is the P05 `LedgerPostingService`, P14 runs
  its public `plan()` (period, accounts, control accounts, FX, balance, dimension rules) and restricts `plan.books` to
  the target book before calling `_persist` (+ `_existing` for idempotency). It switches automatically to a native
  `post_to_book`/`simulate_to_book` once they exist. Purposes carry the book code (`depreciation:NIIF`, …).

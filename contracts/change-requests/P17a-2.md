# CCR P17a-2 — RC/CE PDF routes in treasury and document sources for other modules

* From: P17a · To: P16 (treasury), P10/P11/P12/P13/P15 (document owners) · Type: integration note · Status: OPEN
* P17a answers CCR P16a-4: `documents.service.render_source(uow, company_id, "treasury.receipt" | "treasury.disbursement",
  voucher_id)` renders the recibo de caja / comprobante de egreso with the real renderer (number, party — masked
  without the confidential grant —, lines, totals, valor en letras es-CO, fund, preparer, approvers, watermark
  "SINTÉTICO — sin validez fiscal (DEV)"), stores it once in `documents_generated` with its SHA-256 linked to the
  voucher, and returns the bytes. It checks `documents.render.export` and the voucher's own `treasury.<resource>.read`
  + row scope (404 for foreign ids). The public route already available is `POST /api/v1/documents/render` with
  `{"parameters": {"source_type": "treasury.receipt", "source_id": "<uuid>"}}` (application/pdf).
* Request to P16: serve the contract routes `GET /api/v1/treasury/{receipts|disbursements}/{id}/pdf` and
  `POST …:bulk-print` by calling `render_source` (bulk: `documents.service.create_batch` + `run_batch`).
* Other modules can register a source provider with `documents.sources.register(source_type, provider)` where
  `provider(ctx, company_id, source_id) -> SourceData(template_code, data, number, watermark)`; the provider must read
  through its own policy path (require + scope_queryset + field mask) as the treasury providers do.
* Note for P16 (observation, not changed by P17a): withholding amounts are stored with 4 decimals (e.g. 2.5 % of
  3,000,001.50 = 75,000.0375), so voucher totals are not rounded to the COP minor unit (D-001 says document totals are
  rounded ROUND_HALF_UP to 2 decimals). The PDFs print the D-001 rounded amount (2,925,001.46).

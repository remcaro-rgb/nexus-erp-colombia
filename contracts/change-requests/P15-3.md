# CCR P15-3 — einvoice contract additions found while implementing (to P02, contracts/src → einvoice.yaml)

Status: OPEN (P15, wave 3). The implementation follows the frozen contract exactly (`additionalProperties: false`); these are
additive, backward-compatible requests.

1. `TechnologyProvider`: add read-only `config_state` (DRAFT|TESTED|ACTIVE|RETIRED), `profile_status`
   (SIMULATED|SANDBOX_CONFIGURED|NOT_CONFIGURED, F-PT-OPEN data model), `last_tested_at`, `last_test_passed`.
   Today the UI derives the badge 'SIMULADO — no certificado' and shows the contract report from the `:test-connection` result.
2. `Contingency`: add read-only `kind`, `restored_at`, `deadline_at`, `pending_documents`, `overdue` (48 h countdown). Today the
   UI reads them from `GET /api/v1/kpis/facturacion/panels/contingencia`.
3. `NumberingRange` / `NumberingRangeInput`: add `family` (FE|DEE_POS|DS) and read-only `last_used_number`. Today the family is
   derived from the code prefix (`DS…` → DS, `POS…`/`DEE…` → DEE POS, otherwise FE).
4. `FiscalDocument`: add read-only `issue_date`, `attempts`, `messages[]`, `error_codes[]`, `simulated`. Today they are returned in
   the `summary` item of `GET /documents/{id}/events` (a free-form `Page`).
5. New `GET /api/v1/einvoice/transmissions:export` (text/csv, permission `einvoice.document.export`): transmission log by
   provider/status/date (F-PT-OPEN "Import / export" and "Reports"). Today the log is visible per document in `/events`.
6. `RadianEvent`: add `direction` (EMITTED|RECEIVED), `claim_concept`, `system_generated`. `:emit` takes `claim_concept` in
   `ActionRequest.parameters`.

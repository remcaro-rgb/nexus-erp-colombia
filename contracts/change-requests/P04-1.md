# CCR P04-1 — register the IAM app, routes, authentication and channel (P01 settings/URLs)

* From: P04 · To: P01 (owner of `backend/erp/**`, `pyproject.toml`, `uv.lock`, `backend/kernel/**`) / integrator · Type: wiring (additive) · Status: OPEN
* Why: `backend/iam` is a Django app with models, migrations and routes, but `INSTALLED_APPS`, `erp/urls.py` and
  `REST_FRAMEWORK` belong to P01. Until this CCR is applied, `backend/iam/conftest.py` calls `iam.install.ensure_installed()`
  so the test suite registers the app and its URLs at collection time (no-op once applied). The dev runtime does not serve
  IAM until then.
* Requested changes:
  1. `backend/erp/settings/base.py`: add `"iam"` to `INSTALLED_APPS` (after `"kernel"`).
  2. `backend/erp/urls.py`: `from django.urls import include` and `path("", include("iam.urls"))`.
  3. `REST_FRAMEWORK["DEFAULT_AUTHENTICATION_CLASSES"] = ["iam.authn.InternalAuthentication"]` (IAM views declare their
     own classes, portal views use `iam.authn.PortalAuthentication`; other modules inherit `iam.api.base.SecuredView`).
  4. Optional settings read by IAM (all already passed by `deploy/dev/compose.yaml`): `ERP_OIDC_ISSUER`,
     `ERP_OIDC_INTERNAL_ISSUER` (env fallbacks exist in `iam.oidc.verifier`).
  5. `kernel.tenancy.Channel`: add `PORTAL = "portal"` (the AuditStamp contract lists `portal`; portal requests use `api` meanwhile).
  6. Dependencies: add `PyJWT` + `cryptography` (exact pins) if the integrator prefers a library; `iam.oidc.jwt` implements
     RS256 verification with the standard library today (strict, constant-time full-encoding comparison, RS256 only).
  7. `[tool.coverage.run] source`: add `backend/iam` (omit `backend/iam/tests/*`, `backend/iam/migrations/*`).
* After applying 1–2, `make migrations-check` also covers `iam` (it reports no changes today).

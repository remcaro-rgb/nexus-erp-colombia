# CCR P15-1 — dependencies for real XAdES signing and XSD validation (to P01, owner of pyproject.toml / uv.lock)

Status: OPEN (P15, wave 3). Kind: dependency request + B-06 note.

## Request
Pin (exact versions, after checking their support windows in `docs/dependency-evidence.md`):
* `cryptography` — RSA/PKCS#12 for the XAdES-EPES signature (EG-2) and AES-256-GCM for the evidence envelope;
* `lxml` (or `xmlschema`) — validation of the generated XML against the official DIAN XSDs (T-P15-01);
* optionally `signxml` — maintained XML-DSig layer (ADR-007 suggests it) under our XAdES properties.

## Why
Until then (documented in `docs/handoffs/P15.md`):
* `einvoice.signing` produces the full DIAN signature structure (enveloped reference, SignedProperties, policy identifier) with an
  HMAC-SHA256 key held by the worker — labelled `FIXTURE_NOT_CERTIFIED`; tamper detection is tested (T-P15-04) but DIAN would
  not accept it.
* `einvoice.crypto` encrypts evidence with an encrypt-then-MAC construction built on stdlib HMAC-SHA256 (DEV envelope).
* Golden XML tests check well-formedness/determinism, not the XSDs (hashes of the XSDs are in `docs/compliance/annex-versions.md`).

## B-06 note
The FE annex **v1.9** adopted by Res. 227/2025 art. 1.5.1.10.2 is not linked from the DIAN documentation page on 2026-11-10; the
builders and code lists follow the v1.8 files (hashed). When v1.9 (and DS v1.1, Nómina v1.0, DEE v1.0, RADIAN v1.1) files are
obtained, add a builder set under a new annex version in `einvoice.builders.BUILDERS` with its `valid_from` and new golden files.

# CCR P07-4 — inputs P07 needs from P06, P13 and P18

* From: P07 · To: P06, P13, P18 · Type: integration · Status: OPEN
1. **P06 holiday calendar.** DSR SLAs (Ley 1581 arts. 14–15: 10 + 5 / 15 + 8 business days) need the Colombian
   holiday calendar. Please register an object implementing `workflow.dsr.calendar.HolidayCalendar`
   (`is_holiday(day) -> bool`) with `kernel.services`. Without it the DSR service fails closed (`parameter_unknown`);
   tests use `FixtureHolidayCalendar` with synthetic dates labelled "FIXTURE — NOT LEGALLY VERIFIED".
2. **Every module holding personal data** registers a `workflow.dsr.registry.PersonalDataSource` (subject types,
   fields, finder, optional suppressor, retention rule) at app ready, for DSR discovery/export/suppression.
3. **P13** `manager_of` for approvals (see CCR P07-2 §1) and payroll formulas through
   `FormulaService.evaluate_for_document(uow, company, "payroll", code, inputs, on=..., document_type=..., document_id=...)`.
4. **P10 pricing** uses the same call with domain `pricing`; the snapshot row (`workflow_formula_evaluation`) is
   written inside the caller's unit of work; posted documents are never re-evaluated.
5. **P18** formula import/export (`contracts/dataio/formulas.yaml`): use `FormulaService.export(ctx, company)` and
   `FormulaService.import_json(ctx, company, items)` (imported rows are always DRAFT and must pass their tests before
   submit).
6. **Scheduler job handlers.** Owning modules register handlers for the prompt's job types with
   `workflow.scheduler.registry.register_job_type(code, permission, label, handler, replace=True)`; until a handler is
   registered, runs fail closed ("no handler registered").

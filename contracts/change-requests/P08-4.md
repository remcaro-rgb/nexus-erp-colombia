# CCR P08-4 — `deploy/docker/frontend.Dockerfile`: `corepack prepare --activate` runs before `COPY . .` (OPEN, to P03 / integrator)

Raised by: P08 attempt 2 · Target: P03 (`deploy/docker/frontend.Dockerfile`, not a P08 path).

## Problem
`scripts/ci/build-images.sh` builds the web image only once root `package.json`, `pnpm-lock.yaml` and
`frontend/package.json` exist, so P08 is the first change that exercises this Dockerfile (CI check
"T-P03-01 docker compose up healthy from a clean clone"). The first `RUN` calls `corepack prepare --activate`
with WORKDIR `/` and nothing copied yet. With no `package.json` there, corepack has no `packageManager` to read
and exits 1:
`ERROR: failed to build: … corepack enable && corepack prepare --activate … exit code: 1`.

## Requested change
Do `WORKDIR /src` and `COPY . .` (or just `COPY package.json ./`) **before** the corepack step. The root
`package.json` pins `"packageManager": "pnpm@10.28.0"`. Verified locally with exactly that reordering
(BuildKit secret `proxy_ca` = the session CA): the image builds, `pnpm install --frozen-lockfile` and
`pnpm --dir frontend run build` succeed, Caddy serves `/` and the SPA fallback `/m/inicio` with 200.

## Done on the P08 side (attempt 2)
The frontend build no longer reads `docs/` (that Dockerfile's `.dockerignore` excludes it). The frozen
`docs/spec/ui/{tokens,module-registry}.json` are vendored byte-identically in `frontend/src/lib/spec/ui/`. A
Vitest drift test enforces this, and `pnpm --dir frontend run sync-spec` refreshes them.

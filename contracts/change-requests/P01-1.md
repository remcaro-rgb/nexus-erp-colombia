# CCR P01-1 — kernel error codes for `contracts/errors.yaml`

* From: P01 (kernel) · To: P02 (contracts owner until G0) · Type: additive · Status: OPEN
* Why: `kernel.errors` maps every domain error to RFC 9457 problem+json with a stable `code`. The prompt requires the
  codes to be registered in `contracts/errors.yaml`, which P02 owns.
* Request: add the following codes (HTTP status as implemented in `backend/kernel/errors.py`, source of truth
  `kernel.errors.kernel_error_codes()`), problem `type` = `https://errors.nexus-erp.invalid/<code>`:

```yaml
kernel:
  - code: concurrency_conflict
    status: 409
  - code: conflict
    status: 409
  - code: domain_error
    status: 400
  - code: external_io_in_transaction
    status: 500
  - code: feature_disabled
    status: 403
  - code: idempotency_key_invalid
    status: 400
  - code: idempotency_key_reused
    status: 422
  - code: immutable_record
    status: 409
  - code: not_authenticated
    status: 401
  - code: not_found
    status: 404
  - code: parameter_not_verified
    status: 422
  - code: parameter_unknown
    status: 422
  - code: permission_denied
    status: 403
  - code: precondition_failed
    status: 412
  - code: precondition_required
    status: 428
  - code: retry_exhausted
    status: 503
  - code: sequence_exhausted
    status: 409
  - code: sequence_not_found
    status: 422
  - code: sequence_not_valid
    status: 422
  - code: service_unavailable
    status: 503
  - code: tenancy_not_bound
    status: 500
  - code: unit_of_work_required
    status: 500
  - code: validation_failed
    status: 422
```
* Also mapped from DRF: `method_not_allowed` (405), `throttled` (429), `api_error` (fallback).
* Module classes may override the code on a kernel class (e.g. `Conflict(code="period_closed")`); those module codes stay
  in each module's fragment.

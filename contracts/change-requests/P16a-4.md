# CCR P16a-4 — kernel ParameterUnknown code and the RC/CE PDF routes

* From: P16a · To: P01 (kernel), P17 (documents) · Type: defect note + dependency · Status: OPEN
* `kernel.parameters.enforce` raises `ParameterUnknown(..., code=<parameter code>)`; `DomainError.__init__` treats
  `code=` as the error code, so the problem JSON says `"code": "tax.rate.X"` instead of `parameter_unknown`. Treasury
  catches the class and answers `tax_parameter_unknown` with `errors.parameter=<code>`. Request: pass the parameter code
  as another keyword (e.g. `parameter=`).
* `GET /api/v1/treasury/{receipts|disbursements}/{id}/pdf` and `POST …:bulk-print` need P17's `DocumentRenderer`
  (T-TRE-RC-07 / T-TRE-CE-06 at G3). P16a does not route them yet (no fake endpoint); P17 can render from
  `treasury.api.serializers.voucher_json` (number, party, lines, totals, fund, preparer `audit.created_by`, approvers
  `TreasuryVoucher.approved_by`).

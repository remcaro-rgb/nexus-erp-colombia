# CCR P05-5 — config-less Playwright in `make test-ids` collects vitest files (P01 Makefile, P06, P07)

* From: P05 (attempt 2) · To: P01 (Makefile owner), P06 (`frontend/src/features/tax`), P07 (`frontend/src/features/workflow`),
  integrator · Type: test infrastructure · Status: OPEN
* Symptom: with the P08 JS workspace present, `make test-ids` runs `pnpm --dir frontend exec playwright test --grep …`
  without `--config`. Playwright then loads every `*.spec.*`/`*.test.*` file under `frontend/` before filtering by
  `--grep`. `frontend/src/features/tax/__tests__/model.test.ts` and `frontend/src/features/workflow/__tests__/module.test.ts`
  (vitest files, on `main` since wave 02) abort that collection (`Vitest failed to access its internal state`;
  `module-registry.json needs an import attribute of "type: json"`), so **no** Playwright test of any task runs.
  P08's convention is `__tests__/**/*.unit.ts(x)` exactly to avoid this (see `frontend/vite.config.ts`).
* Requests:
  1. P06 / P07: rename those files to `*.unit.ts` (P08's vitest `include` would then also run them; today vitest ignores them).
  2. P01: give the Playwright call in `test-ids` an explicit config with a narrow `testMatch` (e.g. `*.e2e.ts` and
     `src/features/**/e2e/*.spec.ts`), so one task's unit file cannot break another task's e2e collection.
* Meanwhile (P05): T-ACC-DIM-08 also runs from pytest (`backend/ledger/tests/test_dimension_e2e.py::
  test_T_ACC_DIM_08_dimensions_ui_playwright`) with its own config
  `frontend/src/features/ledger/dimensions/e2e/playwright.config.ts`; it is skipped (not PASSED) while the P08
  workspace is absent, and fails if any of the 5 browser cases fails.
